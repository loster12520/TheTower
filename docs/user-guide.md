## 1. 启动系统

### 1.1 启动后端

```powershell
cd backend
.\gradlew.bat run
```

默认端口是 `8080`。如果端口冲突，可以先设置 `PORT`。

```powershell
cd backend
$env:PORT=8082
.\gradlew.bat run
```

### 1.2 启动前端

```powershell
cd frontend
npm install
npm run dev
```

前端开发环境默认启动在 Umi 的开发端口。若用于 Playwright 联调，项目内已有 `8010` 和 `8011` 两套测试端口配置。

## 2. 创建模板

1. 打开首页。
2. 点击“新建模板”。
3. 输入模板名称和描述。
4. 确认后进入编辑页。

> 新模板默认使用 `schemaVersion 0.0.8`。

## 3. 编排流程

编辑页采用三栏结构。

- 左侧：步骤库。
- 中间：画布。
- 右侧：节点配置或运行面板。

基础编排方式如下。

1. 从左侧步骤库拖拽节点到画布。
2. 按执行顺序把节点连接起来。
3. 选中节点后，在右侧配置面板填写参数。
4. 根据需要继续增加控制流、页面操作或数据处理节点。

## 4. 配置节点

选中节点后，右侧会出现对应的配置表单。

- 页面类步骤常见字段包括选择器、页面别名、超时等。
- 数据类步骤常见字段包括变量名、结果变量、正则表达式等。
- 一些高频字段旁边带有提示图标，可以悬停查看说明。

常见示例。

```text
打开网页 -> 输入文本 -> 点击元素 -> 等待结果 -> 提取数据
```

## 5. 保存模板

完成编排后点击工具栏的“保存”。

- 保存会写入当前 `steps`。
- 非主流程的零散画布节点会写入 `otherStep`。
- 保存成功后，返回首页仍可继续编辑同一模板。

## 6. 普通运行

普通运行适合快速验证流程是否成功。

1. 在编辑页点击“运行”。
2. 系统会创建一次 run。
3. 右侧运行面板会显示当前状态、输出摘要和关键结果。

运行面板默认只显示核心信息。如果需要查看更细的日志、变量或事件流，可以展开“技术详情”。

## 7. 调试运行

调试运行适合排查步骤问题。

1. 点击“调试运行”。
2. 如有断点或“启动即暂停”，流程会在对应位置暂停。
3. 右侧面板可使用“继续”“单步”等控制按钮。
4. 调试预览会显示近实时浏览器画面。

0.0.8 之后，调试结束时浏览器现场可能会被保留。

- 当状态是“运行完成，等待关闭”时，表示 run 已结束，但调试会话仍保留。
- 这时可以继续查看预览、变量和当前路径。
- 若不再需要现场，可点击“关闭调试”。

## 8. 查看日志与产物

运行面板里可以查看三类结果。

- 输出摘要：常见变量输出的简要结果。
- 技术详情：变量、产物、步骤、日志和事件流。
- 调试上下文：当前步骤、页面别名、上下文 ID、变量快照。

若流程产生截图、下载文件或其他产物，后端会把文件写入 `data/runs/` 下对应 runId 的目录。

## 9. 失败定位

当流程失败时，可以按下面方式排查。

1. 在运行面板查看失败提示。
2. 如果面板提供“定位失败节点”，点击后跳转到对应节点。
3. 展开“技术详情”，查看事件流和日志。
4. 若是调试运行，优先查看保留现场和变量快照。

常见失败原因包括。

- 选择器无效。
- 页面别名或上下文目标错误。
- 正则表达式配置错误。
- 元素引用变量为空或顺序越界。

## 10. 常见建议

1. 先用简单模板验证单条链路，再逐步加控制流和复杂步骤。
2. 需要排查问题时优先使用调试运行，而不是反复普通运行。
3. 若要查看完整日志、变量或事件流，记得展开“技术详情”。
4. 真正联调后端时，前端 WebSocket 最好直连后端地址，避免代理带来重复事件或连通性问题。

总结：TheTower 的基本使用链路是“启动系统、创建模板、拖拽配置、保存、运行、调试、查看结果”，只要按这个顺序操作，就能完成多数 RPA 编排任务。
