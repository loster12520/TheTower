# TheTower 0.0.8 技术实现文档

导语：本文档用于记录 0.0.8 的预实施技术方案、关键改造点与风险控制，统一“查缺补漏版”在前后端两侧的实现口径。

## 1. 技术目标

| 目标项 | 状态 | 说明 |
|---|---|---|
| 编辑器体验收口 | 待实现 | 收口左侧步骤库、右侧工作台、滚动边界与暗色主题表现。 |
| 运行语义修正 | 待实现 | 打通跨页自动运行，并修正调试结束后的浏览器保留策略。 |
| 高频步骤补齐 | 待实现 | 新增 `keyboardPress`、`keyboardHotkey`、`textExtract`、`goBack`、`closeOtherPages`。 |
| 元素引用能力收口 | 待实现 | 统一实现 `elementRefVar + elementOrder`，覆盖主要选择器类步骤。 |
| 0.0.7 不回归 | 待实现 | 保持断点、单步、预览、子流程与数据处理稳定。 |

## 2. 后端实现方案

### 2.1 调试生命周期拆分

- 0.0.7 已将 run 生命周期与调试控制绑在同一体系中，但 0.0.8 需要进一步区分“run 是否结束”和“debug session 是否关闭”。
- 后端实现上建议在 `RunService` 中增加 debug session 的独立状态枚举，例如 `ACTIVE`、`PAUSED`、`COMPLETED_WAITING_CLOSE`、`FAILED_WAITING_CLOSE`、`CLOSED`。
- 这样可以保证 run 到达终态后，浏览器仍可保留，前端也能准确表达“调试现场仍在”。

### 2.2 高频步骤实现

- `keyboardPress` 与 `keyboardHotkey` 由 `PlaywrightRunSession` 承接，统一做键名与组合键格式转换。
- `textExtract` 作为纯数据步骤实现，不依赖页面上下文，重点解决正则解析、匹配组提取和异常包装。
- `goBack` 与 `closeOtherPages` 复用当前 page/context 管理能力，避免为页面操作新增独立执行层。

### 2.3 元素引用统一解析

- 目前 `elementRefVar` 与 `elementOrder` 只部分实现，0.0.8 应将其抽为统一解析入口。
- 解析顺序建议固定为：优先消费变量中的元素或元素集合，再在必要时回落到 selector 查询。
- 该能力应服务于 `click`、`type`、`extract`、等待类以及其他涉及目标元素的步骤，减少后续新步骤重复补丁。

### 2.4 事件可读性增强

- 后端在普通运行与调试事件里增加 `stepName`、`stepType`、`stepPathDisplay` 等字段。
- 这能直接支持前端把内部节点 ID 藏到详情里，而把“输入文本”“点击元素”之类步骤名作为默认展示内容。

## 3. 前端实现方案

### 3.1 编辑器布局收口

- 现有编辑页已是三栏结构，0.0.8 不改结构，只收口容器边界、滚动逻辑和视觉层级。
- 核心动作包括：固定编辑页高度、阻止页面总滚动、左右栏独立滚动、收敛面板间距与暗色 token。
- 左侧步骤库优先通过图标统一、标题强化和背景弱化提升观感，而不是引入更复杂的视觉语言。

### 3.2 调试工作台降噪

- `RunPanel` 默认区只保留当前状态、当前步骤、失败定位和调试预览。
- `contextId`、`stepPath`、变量原文、事件流、日志等技术信息折叠进详情区。
- 调试按钮区要更突出，确保继续、单步、打开浏览器、关闭调试是主操作。
- 对于 run 已结束但调试会话保留的状态，前端需显示“现场保留中”，并禁止继续/单步误操作。

### 3.3 跨页自动运行

- 从模板列表点击运行进入编辑页时，前端需要携带一次性运行意图。
- 承接方式可使用路由 state、query 搭配一次性标记，或独立内存 store；关键是必须幂等，只能消费一次。
- 自动运行与编辑页内手动运行应复用同一启动逻辑，避免校验、警告弹窗或 debug 参数产生两套行为。

### 3.4 新步骤配置接入

- `NodeConfigPanel` 补齐键盘步骤、文本提取和页面操作步骤的表单。
- 高风险字段统一增加提示图标和最小可用示例，重点覆盖选择器、变量名、正则表达式、匹配组和元素引用规则。
- `stepRegistry`、校验器与保存加载层必须一起更新，避免再次出现前后端字段漂移。

## 4. 风险与控制

| 风险 | 影响 | 控制策略 |
|---|---|---|
| 跨页自动运行重复触发 | 可能创建重复 run，污染调试状态 | 一次性运行意图只消费一次，并在页面挂载后立即清理 |
| 浏览器保留导致资源泄漏 | 长时间占用本地浏览器与调试会话 | 提供显式关闭入口，并设置可观测的超时清理策略 |
| 元素引用统一化引入回归 | 影响多个既有选择器步骤 | 先在解析层做兼容兜底，再对主要步骤做回归测试 |
| 新步骤配置与执行字段漂移 | 前后端真实运行失败 | schema 文档先冻结，前后端都按同一字段名实现 |
| UI 收口范围失控 | 从局部优化演变成大面积重做 | 仅改编辑器主路径，不扩到首页与全站视觉系统 |

## 6. 与 0.0.7 的承接关系

- 0.0.8 不推翻 0.0.7 的调试状态机，只补齐调试结束后的资源保留语义。
- 0.0.8 不重新设计工作流 schema，只在现有步骤体系上增加少量高频步骤与统一能力。
- 0.0.8 的核心收益在于可用性与一致性，而不是新增大块产品面。

总结：0.0.8 的技术实现重点是把编辑器体验、运行语义和高频步骤做成一套更稳定的闭环，让现有能力真正达到可长期打磨和扩展的工程状态。
