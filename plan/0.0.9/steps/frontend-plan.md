# 0.0.9 前端实施文档（用户交付文档 + 指标验证入口 + 运行参数说明）

导语：本文档用于指导 0.0.9 前端侧工作，重点是把现有编辑器、运行面板和配置能力整理成可交付说明，并为性能验证与效率增强预留落点。

## 1. 实施目标与边界

- 目标：输出面向用户的操作手册，覆盖建模板、编排、运行、调试、查看结果。
- 目标：梳理前端 API / WS 环境变量和 mock / real 联调方式。
- 目标：为 50 节点性能验证和后续效率增强能力提供前端观察点。
- 边界：本阶段优先交付文档与验证，不重构编辑器架构。

## 2. 前端主线

| 模块 | 0.0.9 关注点 |
|---|---|
| 首页与模板卡片 | 作为用户手册中的起点，明确创建、编辑、运行入口 |
| 编辑器页面 | 作为用户手册核心场景，整理步骤库、配置、保存和调试流程 |
| `RunPanel` | 说明核心信息区与“技术详情”折叠区的使用方式 |
| `runtime.ts` | 固化 API / WS / 鉴权 / 日志相关环境变量说明 |
| Playwright 配置 | 明确 mock 与真实联调的运行方式与端口 |

## 3. 交付重点

### 3.1 用户手册

- 从启动前后端开始写，而不是默认读者已熟悉工程结构。
- 覆盖模板创建、保存、普通运行、调试运行、失败定位与产物查看。
- 对“技术详情折叠区”“调试保留现场”等 0.0.8 新语义要明确写清。

### 3.2 环境变量与联调说明

- 说明 `UMI_APP_API_BASE_URL`、`UMI_APP_WS_BASE_URL`、`UMI_APP_LOG_LEVEL` 等变量。
- 说明 mock 与真实联调两种 Playwright 配置差异。
- 说明真实联调时为什么需要直连后端 WS。

### 3.3 性能与效率增强入口

- 为 50 节点性能验证定义场景和观察点。
- 评估自动保存、搜索、克隆、自动布局的最小可落地方案。

## 4. 测试重点

1. 用户手册步骤是否能在当前 UI 上逐条复现。
2. 文档描述的按钮、面板和术语是否与当前界面一致。
3. mock / real 联调说明是否能直接对应现有 Playwright 配置。

## 5. 实施顺序

1. 输出 `docs/user-guide.md`。
2. 输出 `docs/deployment.md` 里的前端部分。
3. 补专项验证文档中的前端观察口径。
4. 再评估效率增强项是否进入实现。

总结：0.0.9 前端侧优先把“已有体验写清楚、跑清楚、讲清楚”，再决定是否补更多增强能力。
