# 0.0.9 后端实施文档（指标验证支撑 + 部署规范 + 文档补完）

导语：本文档用于指导 0.0.9 后端侧工作，重点是为浏览器兼容、并发执行、成功率统计和部署交付提供稳定支撑，而不是继续横向扩步骤类型。

## 1. 实施目标与边界

- 目标：补齐浏览器兼容与并发执行专项测试所需的后端支撑。
- 目标：整理部署配置、错误码和调试状态，使文档与实现一致。
- 目标：为成功率、耗时、失败原因统计提供最小可用的数据基础。
- 边界：不重做执行引擎，不新增大规模外部集成节点。

## 2. 后端主线

| 模块 | 0.0.9 关注点 |
|---|---|
| `RunService` | 支撑并发运行验证、运行结果统计与事件可追溯性 |
| `PlaywrightRunExecutor` | 明确 Chromium / Firefox / Edge 的真实支持方式 |
| `application.conf` 与入口 | 固化端口、数据库路径、浏览器配置与 `PORT` 覆盖口径 |
| 错误码与异常层 | 输出可文档化的错误码说明 |
| 测试脚本 | 追加性能、兼容、并发专项验证脚本 |

## 3. 实施拆分

### 3.1 浏览器兼容验证支撑

- 明确当前浏览器配置入口与缺省值。
- 梳理 Chromium、Firefox、Edge 的实际运行方式。
- 若 Edge 依赖 Playwright channel 或系统安装，需要把真实限制写进部署文档。

### 3.2 并发与稳定性验证支撑

- 复用现有 `POST /api/v1/runs` 和 `GET /api/v1/runs/{id}` 完成并发验证。
- 确保同批运行的事件流、状态和产物目录能按 runId 分离。
- 为专项测试输出耗时、终态和失败原因汇总提供最小辅助字段。

### 3.3 部署口径收口

- 校验 `application.conf`、`EngineMain`、`PORT` 和 README 的一致性。
- 明确 SQLite 路径、运行产物路径和构建产物路径。
- 记录本地部署与后续容器化需要的关键依赖。

### 3.4 错误码文档化

- 把模板、运行、调试、页面步骤、文本提取、元素顺序等错误码归类整理。
- 错误码文档只覆盖当前稳定可见的业务码，不写推测字段。

## 4. 测试重点

1. Chromium、Firefox、Edge 下主流程执行是否一致。
2. 至少 3 个流程同时运行时，状态与事件是否隔离。
3. 异常时错误码是否稳定、可复现、可写入文档。
4. 部署文档中的端口、路径和启动命令是否可直接复现。
