# 0.0.6 后端实施文档（调试会话 + 预览帧 + DevTools 入口）

导语：本文档用于指导 0.0.6 后端实现，重点解决调试模式、预览帧推送、宿主机可见浏览器与 DevTools 打开能力。

## 1. 实施目标与边界

- 目标：在 0.0.5 run 生命周期基础上加入调试会话。
- 目标：支持近实时预览帧推送与多标签页、多上下文元数据同步。
- 目标：提供本地开发环境下的可见浏览器与 DevTools 打开能力。
- 边界：不在本版实现远程点击、远程输入与断点单步控制。

## 2. 后端改造主线

| 模块 | 当前现状 | 0.0.6 目标 |
|---|---|---|
| `RunService` | 已负责 run 生命周期与事件推送 | 增加 debug session 生命周期与调试状态管理 |
| `PlaywrightRunSession` | 已支持 page/context 基础管理 | 增加调试模式、预览帧采样与可见浏览器语义 |
| WebSocket 路由 | 已承载运行事件 | 新增调试事件推送能力 |
| routes | 仅有 run 基础控制 | 新增 debug open-browser、close 等接口 |

## 3. 模块拆分建议

### 3.1 `RunService` 负责调试会话生命周期

- 维护 run 与 debug session 的关联关系。
- 负责 debug start、debug close、debug error 的事件发射。
- 保持普通运行模式与调试模式共用同一套 run 状态机。

### 3.2 `PlaywrightRunSession` 负责预览帧与可见浏览器

- 新增调试模式配置：
  - 是否非 headless
  - 是否打开 DevTools
  - 预览帧率
  - 预览压缩质量
- 周期性采样当前页面预览帧并返回最小必要元信息。
- 在多标签页切换后更新当前预览来源页面。

### 3.3 路由层负责调试控制入口

- `open-browser`：尝试在宿主机打开可见浏览器与 DevTools。
- `close`：主动关闭调试会话。
- 所有失败必须返回结构化错误与 requestId。

## 4. 公共能力要求

### 4.1 预览帧节流

- 调试帧必须支持频率限制。
- 推荐默认值 2 到 4 fps。
- 若 run 当前没有可预览页面，应推送状态事件而不是空帧循环。

### 4.2 page/context 元数据同步

- 每一帧或状态更新都应附带：
  - `contextId`
  - `pageAlias`
  - 时间戳
- 页面切换后应尽快切换预览来源，避免前端画面与 run 当前页错位。

### 4.3 可见浏览器与 DevTools

- 可见浏览器只在本地开发调试模式启用。
- 打开失败时应区分：
  - 环境不支持
  - 浏览器未处于调试模式
  - run 已结束

## 5. 测试重点

1. 调试会话建立与关闭黑盒。
2. 多标签页场景下 `pageAlias` 与帧来源同步。
3. 多上下文场景下 `contextId` 同步。
4. 普通运行模式不推送调试帧。
5. DevTools 打开接口在本地模式下可用，失败时有明确错误。

## 6. 实施顺序

1. 定义调试配置与调试事件模型
2. 扩 `PlaywrightRunSession` 预览帧采样能力
3. 扩 `RunService` 调试会话与状态管理
4. 补 routes 与 WebSocket 通道
5. 补后端黑盒与多标签页调试脚本

总结：0.0.6 后端的重点不是另起一套调试执行器，而是在既有 run 基础上增加“可观测调试层”，让调试模式与默认模式长期可共存。
