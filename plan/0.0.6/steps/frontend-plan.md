# 0.0.6 前端实施文档（调试预览 + 画布编辑器交互）

导语：本文档用于指导 0.0.6 前端实现，重点解决运行预览、全屏调试、左右端口、无抖动选中态和编辑器快捷操作。

## 1. 实施目标与边界

- 目标：让运行面板升级为可承载调试预览的调试工作台。
- 目标：让画布节点连接方式更符合横向编排习惯。
- 目标：让复制、剪切、粘贴、撤销和自动连线成为真实可用的编辑能力。
- 边界：不在本版新增独立调试页面，不重写编辑器整体架构。

## 2. 前端改造主线

| 模块 | 当前现状 | 0.0.6 目标 |
|---|---|---|
| `RunPanel` | 只有状态、日志、事件、摘要 | 增加近实时预览、全屏、调试入口 |
| `runStore` | 只维护 run 事件与摘要 | 增加 debug session、frame buffer、fullscreen 状态 |
| `nodes` | 端口上下布局，选中时 border 变宽 | 改为左右端口与稳定选中态 |
| `editorStore` | 无 history、clipboard | 增加复制、剪切、粘贴、撤销、重做 |
| `EditorPage` | 仅支持保存与删除快捷键 | 增加 Ctrl/Cmd+C/X/V/Z/Y 与自动连线体验 |

## 3. 运行调试界面建议

### 3.1 运行面板布局

- 顶部：run 状态、当前路径、当前 page/context。
- 中部：调试预览卡片与全屏按钮。
- 下部：outputs、artifacts、日志、事件流。

### 3.2 全屏预览

- 预览区域允许打开 modal 或 drawer 式全屏查看。
- 全屏时保留最少调试信息：run 状态、pageAlias、contextId、关闭按钮。

### 3.3 调试入口

- 运行前或运行后都应有明确调试入口，但交互要清晰区分“普通运行”和“调试运行”。
- 若当前 run 不是调试模式，应禁用“打开 DevTools”并给出说明。

## 4. 画布体验改造

### 4.1 节点端口方向

- `CustomNodeComponent` 与容器节点统一改为左进右出。
- 连线曲线与方向样式同步调整。

### 4.2 选中态稳定性

- 边框宽度固定，不允许再用 1px/2px 切换。
- 选中高亮改为边框颜色、阴影或 outline。

### 4.3 history 与 clipboard

- `editorStore` 应提供：
  - `copySelectedNodes`
  - `cutSelectedNodes`
  - `pasteClipboard`
  - `undo`
  - `redo`
- history 记录建议以“图快照”或“命令边界”实现，不建议零碎记录到每个字段输入字符级。

### 4.4 自动连线

- 优先基于 React Flow 配置与拖拽结束逻辑实现近距离吸附。
- 阈值先取 50px 左右，并在真实使用中再微调。
- 自动连线触发后仍通过 `editorStore.addEdge` 落边，统一服从当前约束。

## 5. 测试重点

1. mock E2E：左右端口可见，选中无抖动。
2. mock E2E：复制、剪切、粘贴、撤销、重做。
3. mock E2E：50px 自动连线生效，非法边仍被拦截。
4. 真实联调：运行预览出现、全屏打开、page/context 标签变化。
5. 真实联调：调试入口状态与错误提示稳定。

## 6. 实施顺序

1. 扩 `runStore` 与 `RunPanel` 调试状态模型
2. 接入调试帧与全屏预览 UI
3. 改节点左右端口与稳定选中态
4. 补 `editorStore` 的 clipboard/history 能力
5. 补快捷键与自动连线
6. 补 mock 与真实联调回归

总结：0.0.6 前端的重点是把“运行时可看、编辑时顺手、选中时不抖、连接时少操作”变成默认体验，而不是继续堆更多配置面板。
