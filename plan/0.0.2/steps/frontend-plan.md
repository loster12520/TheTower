## 1. 实施目标与边界

### 1.1 0.0.2 前端目标
1. 建立运行时配置中心：API/WS 地址、鉴权策略、日志开关可动态注入。
2. 建立统一请求层：拦截器、错误兜底、token/header 自动注入、环境地址自动切换。
3. 建立统一 WebSocket 层：单例工厂、自动重连、心跳、消息加解密封装。
4. 完成样式规范化：内联样式迁移到 SCSS，组件聚焦结构与状态逻辑。
5. 目录按页面域收敛，并统一 `@` 别名导入。
6. 建立主题切换能力（至少明暗双主题）。

### 1.2 不变边界
- 不做大规模视觉重设计，只做结构规范化。
- 不新增复杂业务节点类型。
- 保持现有核心页面流程：模板列表、编辑、运行监控。

## 2. 模块职责地图（前端）

| 目录 | 职责 | 约束 |
|---|---|---|
| `pages/**` | 页面编排与路由级交互 | 不放通用请求逻辑 |
| `components/**` | 可复用 UI 组件 | 不直接依赖页面 store 细节 |
| `stores/**` | 状态与业务视图模型 | 动词方法命名统一，状态名词化 |
| `services/**` | API 与 WS 调用封装 | 统一入口，禁止页面直连网络 |
| `utils/**` | 纯工具函数 | 不产生副作用 |
| `models/**` | 类型定义与数据结构 | 与后端协议对齐 |

## 3. 分阶段实施清单

### Phase A：目录与 import 规范收敛（优先级 P0）

#### A.1 `@` 别名全面落地
- `src` 下导入统一改为 `@/...`。
- 禁止新增深层相对路径（如 `../../../`）。
- 构建与类型系统需同时支持别名（`tsconfig` + 构建配置）。

#### A.2 页面域资源收敛
- 以页面域为中心组织相关资源（例如编辑页相关逻辑收敛到 `editor` 域）。
- 页面私有组件优先放页面域目录，通用组件再上提到 `components`。

### Phase B：运行时配置中心（优先级 P0）

#### B.1 配置模型
- 必含配置项：
  - `apiBaseUrl`
  - `wsBaseUrl`
  - `auth.enabled`
  - `auth.tokenHeader`
  - `log.enabled`
  - `log.level`

#### B.2 注入策略
- 开发/测试/生产可切换。
- 禁止在页面组件中硬编码地址。
- 配置读取失败需降级到安全默认值并输出告警日志。

### Phase C：统一请求层（优先级 P0）

#### C.1 请求入口统一
- 整理到单一请求客户端（建议在 `services` 层统一导出）。
- 接入请求拦截、响应拦截、错误标准化解析。

#### C.2 鉴权与 header 注入
- 根据运行时配置自动注入 token/header。
- 支持关闭鉴权开关（便于本地联调）。

#### C.3 错误兜底与开发日志
- 统一处理 `error.code`，输出前端友好提示。
- 开发环境打印请求摘要（method/url/status/requestId）。

### Phase D：统一 WebSocket 层（优先级 P0）

#### D.1 单例工厂
- 提供按 `string key` 获取连接实例的工厂函数。
- 同 key 复用连接，不同 key 隔离。

#### D.2 自动重连
- 指数退避策略，最大重试次数可配置。
- 到达上限后输出可见错误状态，避免无限重连。

#### D.3 心跳与消息加解密
- 心跳保活（ping/pong 或心跳包）。
- 消息统一过加解密适配层（先最小可用实现，后续可替换）。

### Phase E：主题体系与样式规范化（优先级 P1）

#### E.1 主题切换
- 提供明暗双主题切换能力。
- 主题变量可被页面与组件继承。

#### E.2 内联样式迁移
- TSX 内联样式迁移到 `.scss`。
- 新增组件禁止大段内联样式。
- 样式文件命名与组件命名保持一致。

### Phase F：注释与命名规范化（优先级 P0）

#### F.1 白名单注释覆盖
- 范围：
  - `frontend/src/pages/**`
  - `frontend/src/stores/**`
  - `frontend/src/services/**`
- 要求：
  - 文件头职责说明；
  - 对外函数注释（意图 + 输入输出 + 边界行为）；
  - 关键副作用代码块注释。

#### F.2 命名词典执行
- 函数使用动词：`get/create/update/delete/start/cancel/restart/validate/parse/emit`。
- 状态使用名词：`template/run/status/event/payload/response/context/cache`。
- 缩写需收敛，避免同义多写。

## 4. 规范落地与质量门禁

### 4.1 阈值规则
- 圈复杂度：`<= 10`
- 单函数长度：建议 `<= 60`
- 单文件长度：`<= 400`

### 4.2 自动化检查
- lint 规则需覆盖：复杂度、文件长度、导入路径规范。
- CI 中将规则设为阻断项（或必须附豁免记录）。

### 4.3 注释白/灰/黑名单执行
- 白名单：高密度注释，目标合规率 `>= 95%`。
- 灰名单：简要注释，关键语义必注释。
- 黑名单（构建产物、依赖、生成文件）：禁止注释膨胀。

## 5. 回归清单与验收口径

### 5.1 功能回归清单
1. 模板列表加载、创建、删除。
2. 编辑页节点配置、保存。
3. 发起运行、接收 WS 事件、停止运行。
4. 运行异常时提示符合错误码语义。

### 5.2 规范与基建验收
- `@` 别名导入使用率达到 100%（`src` 内）。
- 样式抽离率达到目标（新增或改造文件不再出现大段内联样式）。
- 请求层与 WS 层统一入口生效，散落入口显著减少。
- 主题切换可实际生效且组件可继承样式变量。

## 7. 风险与缓解策略

### 7.1 主要风险
- 导入路径批量替换导致构建失败。
- WS 重连策略不当导致重复连接或状态抖动。
- 样式迁移期间出现视觉回归。

### 7.2 缓解策略
- 先落地别名配置，再分目录迁移导入。
- 对 WS 工厂增加连接状态机与实例复用测试。
- 样式迁移按页面分批，完成一页回归一页。

总结：前端 0.0.2 以“统一入口、配置驱动、样式收敛、可验证规范”为目标，通过分阶段实施降低重构风险并提升后续迭代效率。
