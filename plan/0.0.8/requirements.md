## 范围与非目标

- 范围：重做编辑页左右面板的视觉层次、信息组织与滚动边界。
- 范围：修复运行入口与调试结束语义，让运行与调试行为符合用户直觉。
- 范围：新增 `keyboardPress`、`keyboardHotkey`、`textExtract`、`goBack`、`closeOtherPages`。
- 范围：补齐 `elementRefVar + elementOrder` 的完整支持。
- 范围：本版测试重点覆盖体验收口、运行语义与新增步骤，并要求 0.0.7 调试能力不回归。
- 非目标：不在本版继续扩展文件、Excel、邮件、Google Sheet、请求监听等外部集成能力。
- 非目标：不做条件断点、表达式断点、时间旅行调试、预览远程操控。
- 非目标：不做模板市场、计划任务、用户体系与协作能力。
- 非目标：不把 0.0.8 做成全站视觉重构，改动聚焦编辑器与运行相关核心路径。

## 版本目标

| 目标项 | 优先级 | 说明 | 验收信号 |
|---|---:|---|---|
| 编辑器视觉平衡 | P0 | 左右侧栏、标题层次、图标风格和滚动边界更协调 | 编辑页首屏更整洁，重点信息一眼可分层 |
| 调试面板易读性 | P0 | 默认展示用户看得懂的信息，不把内部 ID 暴露为主信息 | 用户可直接知道当前在哪个步骤、能做什么操作 |

| 调试保留现场 | P0 | 调试结束后保留浏览器现场，方便继续排查 | 用户无需重新运行即可继续观察页面状态 |

## 承接基线（来自 0.0.7）

- 0.0.7 已完成：断点、暂停、继续、单步、变量快照与调试预览。
- 0.0.7 已完成：`callWorkflow`、`convertJson`、`extractKey`、`randomGet`。
- 0.0.8 不重写 0.0.7 的调试状态机，而是在现有能力上收口面板体验与默认行为。
- 0.0.8 不重新设计画布核心交互，而是修复左右面板、滚动容器和步骤缺口。

> 说明：0.0.8 的关键词不是“再加很多功能”，而是把已有功能的**可用性**和缺失的**高频基础能力**补到位。

## 0.0.8 体验收口

### 1. 左侧步骤库视觉重做

- 左侧步骤库的分类标题应显著强于步骤项名称，至少在字号、字重或颜色对比上形成清晰层级。
- 各步骤图标应统一尺寸、统一基线和统一绘制风格，优先采用黑白或单色 SVG 方案。
- 步骤项底部不再依赖大面积类别底色区分，可统一为浅灰或弱对比背景，以避免页面过花。
- 左侧栏的右内边距需要与滚动条保持舒适距离，避免视觉上“右侧过挤、左侧过空”。
- 若类别配色继续保留，应只作为小面积点缀，而不是成为主背景色。

### 2. 右侧运行监控面板降噪

- `RunPanel` 默认只展示两个主板块：基础信息、调试预览。
- `stepPath`、`contextId`、变量原文、事件列表、日志等技术细节移入“详情”折叠区。
- 当前步骤、最近失败步骤、调试暂停步骤应优先显示用户可理解的步骤名称，如“输入文本”“点击元素”，不直接显示 `node_xxx`。
- 当步骤名被 hover 或点击时，应支持高亮或定位到画布上的对应节点。
- 调试预览区按钮应重新排布并放大，确保“继续”“单步”“打开浏览器”“关闭调试”是主操作而非附属文字。
- 面板内容应优先回答三个问题：当前运行到哪、现在能做什么、如果失败该看哪里。

### 3. 编辑页滚动边界修复

- 编辑页不应出现页面级总滚动条。
- 左侧步骤库与右侧配置/调试面板各自独立滚动。
- 中央画布只保留 ReactFlow 自身的平移、缩放和视口交互，不被页面滚动影响。
- 顶部工具栏、子流程浮层、调试浮层在窗口高度变化时不应把页面整体撑出滚动。

### 4. 配置项提示体系补齐

- 节点配置面板中的关键字段应提供提示图标。
- hover 提示需解释字段用途、常见填写方式和典型示例，避免只重复字段名称。
- 首批补齐范围至少覆盖高频字段：选择器、变量名、等待方式、条件表达式、输出变量、键盘参数、正则参数。
- 提示文案应尽量短，优先解决“这个字段是干什么的”和“我该怎么填”。

### 5. 暗色主题修复

- 编辑器左右面板、浮层、卡片、标签、描述文本、边框和预览区域都必须在暗色主题下具备可读对比度。
- 不允许出现亮色模式正常、暗色模式文字发灰看不清或背景层级塌陷的问题。
- 暗色主题应沿用统一颜色 token，不允许在局部组件硬编码一套不兼容颜色。
- 运行状态、错误态、成功态、暂停态在暗色下仍需保持明确的语义颜色区分。

## 0.0.8 运行语义修正

### 1. 列表运行自动启动

- 用户从模板列表或其他入口点击“运行”后，若系统需要跳转到编辑页，应自动承接这次运行意图并开始执行。
- 不允许出现“点击运行，结果只跳转页面但未启动运行”的行为落差。
- 若运行前仍需校验或警告弹窗，应保持与编辑页直接点击运行一致的校验口径。
- 同一运行意图只能消费一次，避免刷新或重复进入编辑页导致重复启动。

### 2. 调试运行保留浏览器

- 调试运行完成后，默认策略应为“停止执行但保留浏览器与现场”。
- 用户可在调试面板中主动关闭调试会话或关闭浏览器，而不是由系统在成功结束时立即回收。
- 若调试运行失败，也应尽量保留失败现场，方便查看错误页面状态。
- 为避免资源长期占用，可提供显式关闭入口与必要的超时清理策略，但这不应改变默认“先保留”的产品语义。

## 0.0.8 高频能力补洞

### 1. keyboardPress

- 新增 `keyboardPress` 节点，用于发送单个按键。
- 至少支持：Backspace、Tab、Enter、Space、Escape、Delete、ArrowUp、ArrowDown、ArrowLeft、ArrowRight。
- 节点配置应支持直接选择常用键，而不是要求用户记忆底层 Playwright 键名。
- 执行失败时应返回结构化错误，而不是静默跳过。

### 2. keyboardHotkey

- 新增 `keyboardHotkey` 节点，用于发送组合键。
- 至少支持 Control、Meta、Shift、Alt 与常用字母或方向键组合。
- 节点配置应避免让用户手写复杂字符串，优先提供结构化录入或可选项组合。
- 在不同平台上需要定义明确的默认行为，避免组合键语义漂移。

### 3. textExtract

- 新增 `textExtract` 节点，用于从输入文本中按正则提取内容。
- 输入至少支持：纯文本、变量引用字符串。
- 配置至少支持：正则表达式、匹配组索引、是否全局匹配、输出变量名。
- 未匹配时的默认行为必须固定，例如返回空字符串、空数组或结构化错误，不能依赖实现细节。
- 正则非法时必须返回明确错误信息。

### 4. ElementRef 与 elementOrder 补齐

- 选择器类步骤应支持通过 `elementRefVar` 直接引用前置提取或查找得到的元素或元素集合。
- 当目标是元素集合时，应支持 `elementOrder` 指定固定索引、首个、最后一个或随机一个元素。
- `elementRefVar` 与传统 `selector` 的优先级、互斥关系和缺省行为必须在文档与实现中保持一致。
- 该能力应在主要相关步骤中统一生效，而不是只在个别节点临时支持。

### 5. goBack 与 closeOtherPages

- 新增 `goBack` 节点，语义为当前页面执行浏览器后退。
- 新增 `closeOtherPages` 节点，语义为关闭当前上下文中的其他页面，并允许保留当前页或指定别名页。
- 若页面数量不足或目标页不存在，错误行为要明确且可观测。
- 这两个步骤应完整接入步骤库、配置面板、模板保存加载、执行器与运行事件流。

## 前后端实现约束

### 前端约束

- 体验收口优先基于现有 `RunPanel`、`NodeConfigPanel` 与编辑页三栏布局增强，不新增分叉页面。
- 所有新增步骤必须完整接入步骤库、节点配置、保存加载、导入导出、节点渲染与运行定位链路。
- 暗色主题修复应优先回到统一 token 与样式变量层，不允许在 TSX 内零散追加内联样式兜底。
- 运行自动启动必须具备幂等保护，避免页面重复挂载时重复启动。

### 后端约束

- 新增步骤必须遵循既有步骤执行模型、错误码与事件流，不允许形成只对某一步骤特殊处理的不可维护分支。
- `elementRefVar + elementOrder` 的解析必须由统一能力层兜底，而不是分散在各步骤实现里。
- 调试运行结束保留浏览器时，run 生命周期结束与 debug 会话生命周期结束要明确区分。
- `goBack`、`closeOtherPages`、键盘步骤和 `textExtract` 的空值、失败和边界行为必须先在协议中固定。

### 协议约束

- 不破坏 0.0.7 已有调试事件协议与字段兼容性。
- 新增步骤 schema、默认值、错误行为和输出变量写回规则必须文档先行。
- 对用户可见的步骤显示名称、类型名称和调试描述要统一词典，避免前后端各说一套。

## 测试与验收口径

1. 编辑器体验回归
   - 在亮色和暗色主题下分别打开编辑页。
   - 验收点：左右栏层次清晰，无页面级总滚动条，暗色文字和状态可读。

2. 调试面板降噪回归
   - 发起调试运行并观察右侧面板。
   - 验收点：默认只显示核心板块，当前步骤名称可读，常用按钮位置明确，详情可展开查看技术信息。

3. 列表运行自动启动闭环
   - 从模板列表点击运行并跳转到编辑页。
   - 验收点：跳转后自动发起运行，且不会重复启动。

4. 调试浏览器保留闭环
   - 发起调试运行直至成功或失败。
   - 验收点：执行结束后浏览器仍保留，用户可主动关闭调试会话。

5. 键盘步骤闭环
   - 使用 `keyboardPress` 与 `keyboardHotkey` 完成输入、提交或快捷操作。
   - 验收点：按键行为符合预期，异常输入返回稳定错误。

6. 文本提取闭环
   - 使用 `textExtract` 从变量文本中按正则提取内容。
   - 验收点：匹配结果按配置写回变量，非法正则与未匹配场景行为稳定。

7. 元素引用增强闭环
   - 前置步骤生成元素集合，后续步骤通过 `elementRefVar + elementOrder` 消费。
   - 验收点：可按首个、最后一个、指定索引或随机策略稳定命中元素。

8. 页面操作步骤闭环
   - 使用 `goBack` 与 `closeOtherPages` 组织多页面流程。
   - 验收点：页面回退与标签页关闭行为可观测、可定位、失败可提示。

9. 0.0.7 回归
   - 复跑断点、单步、预览、子流程与数据处理主链路。
   - 验收点：0.0.7 核心能力全部继续通过。

总结：0.0.8 的交付标准是“编辑器更顺眼、调试更顺手、运行更符合直觉、常用步骤更完整”，先把这四条高频主链路收口，再继续扩更重的外部集成能力。
