# 0.0.8 前端实施文档（编辑器收口 + 调试面板降噪 + 新步骤配置）

导语：本文档用于指导 0.0.8 前端实现，重点解决编辑器左右栏视觉收口、运行监控可读性、跨页自动运行承接，以及高频新增步骤的配置接入。

## 1. 实施目标与边界

- 目标：重做编辑器左右栏的层次、间距、滚动边界和暗色主题一致性。
- 目标：把 `RunPanel` 从“技术信息堆叠”收口为“默认可读、细节可展开”的调试工作台。
- 目标：让模板列表点击运行后进入编辑页即自动启动，并且只触发一次。
- 目标：让新增高频步骤完整接入步骤库、配置表单、校验、保存加载与调试定位。
- 边界：不在本版重写 ReactFlow 画布架构，不新增独立运行页或独立调试页。

## 2. 前端改造主线

| 模块 | 当前现状 | 0.0.8 目标 |
|---|---|---|
| `pages/editor` | 已有三栏布局与调试运行入口 | 去掉页面总滚动条，统一左右栏滚动与亮暗主题表现 |
| `RunPanel` | 已支持调试预览、继续、单步、日志与上下文展示 | 默认只保留核心信息，技术细节折叠，按钮更突出 |
| `NodeConfigPanel` | 已覆盖 0.0.7 节点配置 | 补齐提示图标体系和新增步骤表单 |
| `editorStore` | 已维护画布、步骤选择和断点集合 | 承接跨页运行意图、节点 hover/定位高亮和步骤可读名映射 |
| `runStore` | 已维护 run、debug session、事件与变量快照 | 支持待关闭调试态、步骤显示名、自动运行幂等控制 |
| `stepRegistry` / `validator` / 转换层 | 已覆盖 0.0.7 步骤 | 纳入 0.0.8 新步骤与 `elementRefVar + elementOrder` 配置校验 |

## 3. 编辑器收口建议

### 3.1 左侧步骤库

- 分类标题字号、字重和留白要显著强于步骤项。
- 步骤图标统一尺寸和风格，优先使用单色 SVG 或等宽图标容器。
- 步骤项背景统一弱化，只保留轻量 hover 与选中反馈。
- 左栏滚动容器增加右侧内边距，避免贴着滚动条。

### 3.2 右侧工作台与配置栏

- `RunPanel` 与 `NodeConfigPanel` 共用一致的卡片节奏、标题层级和间距规则。
- 右栏在调试态与配置态之间切换时，不应出现明显布局跳变和滚动重置问题。
- 暗色主题下右栏的卡片、标签、二级文本和分割线都应复用统一 token。

### 3.3 滚动边界

- 编辑页根容器固定高度并阻止页面整体滚动。
- 左右栏内部滚动分别独立，中央画布保持 `overflow: hidden`。
- 浮层组件高度要受控，避免把页面整体撑出视口。

## 4. 调试工作台建议

### 4.1 默认信息层级

- 第一层：运行状态、当前步骤名称、失败定位、调试状态。
- 第二层：调试预览与常用按钮。
- 第三层：详情折叠区，放置 `stepPath`、`contextId`、变量原文、事件流和日志。

### 4.2 节点名称与画布联动

- 面板默认显示步骤中文名或节点别名，不直接显示内部 ID。
- hover 当前步骤或失败步骤时，应触发画布节点高亮。
- 点击“定位当前节点”或“定位失败节点”时，应复用现有 `focusStepPath` 一类能力，而不是新造定位分支。

### 4.3 调试结束待关闭态

- 当 run 已结束但浏览器保留时，面板要明确显示“调试现场保留中”。
- 此时继续和单步按钮禁用，保留“打开浏览器”“查看详情”“关闭调试”入口。
- 前端不能把此状态误判成调试会话已结束并直接清空预览信息。

## 5. 新步骤配置接入

### 5.1 `keyboardPress`

- 表单优先提供常用按键下拉选择。
- 若支持手动输入高级键名，也要给出提示与校验。

### 5.2 `keyboardHotkey`

- 表单建议拆分为修饰键多选和主键单选/输入，而不是一整个字符串输入框。
- UI 中的展示文案需与后端标准键名映射解耦。

### 5.3 `textExtract`

- 表单最少包含：输入文本、正则表达式、匹配组索引、全局匹配开关、输出变量。
- 对正则输入要配清晰提示，告诉用户常见例子与匹配组含义。

### 5.4 `goBack` / `closeOtherPages`

- `goBack` 可保持极简配置。
- `closeOtherPages` 至少提供“保留当前页 / 保留指定别名页”两种模式。

### 5.5 `elementRefVar + elementOrder`

- 对涉及元素目标的表单统一补齐“从变量引用元素”入口。
- `elementOrder` 优先提供枚举选择：首个、最后一个、指定索引、随机一个。
- 表单上要明确提示 `selector` 与 `elementRefVar` 的优先级规则。

## 6. 测试重点

1. mock E2E：编辑页无页面级总滚动条，左右栏独立滚动。
2. mock E2E：亮色与暗色主题下 `RunPanel` 和 `NodeConfigPanel` 可读。
3. mock E2E：从模板列表点击运行后，编辑页自动启动且不会重复触发。
4. mock E2E：`RunPanel` 默认仅显示核心板块，详情折叠后可查看技术信息。
5. mock E2E：新增步骤表单可配置、保存、重载与校验。
6. 真实联调：调试运行结束后进入待关闭态，浏览器现场保留。
7. 真实联调：键盘步骤、文本提取、页面后退与关闭其他页面闭环通过。

## 7. 实施顺序

1. 收口编辑页容器、左右栏样式与暗色 token
2. 重构 `RunPanel` 信息层级与待关闭调试态 UI
3. 实现跨页自动运行意图承接与幂等保护
4. 接入新增步骤与 `elementRefVar + elementOrder` 表单能力
5. 补 mock 与真实联调测试

总结：0.0.8 前端的关键不是新增一个更复杂的界面，而是把编辑器现有主路径磨顺，让调试、运行和配置都更贴近用户直觉。
