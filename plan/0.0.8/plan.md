# 0.0.8 版本目标（体验收口 + 高频能力补洞）

导语：本版本聚焦把 0.0.7 暴露出的编辑器体验问题与高频能力缺口一次收口，优先解决“能用但不好用、能调试但不顺手、常用步骤还不完整”三类问题。

## 1. 版本目标

| 目标项 | 优先级 | 说明 | 验收信号 |
|---|---:|---|---|
| 编辑器视觉与布局收口 | P0 | 修复左侧步骤栏、右侧面板、全局滚动条与暗色主题不协调问题 | 编辑页在亮色与暗色下都保持稳定、平衡、无多余总滚动条 |
| 调试面板信息降噪 | P0 | 将右侧运行监控从“技术信息堆叠”调整为“用户可读的调试工作台” | 面板默认只展示关键信息，节点名称可读，常用操作更突出 |
| 运行与调试语义修正 | P0 | 修复“从列表点击运行跳转后不自动启动”和“调试完成后自动关闭浏览器”两类行为问题 | 从入口发起运行后可自动开始；调试完成后浏览器默认保留 |
| 高频缺失步骤补齐 | P0 | 补齐 `keyboardPress`、`keyboardHotkey`、`textExtract` 三类高频步骤 | 常见键盘交互与正则提取无需再依赖脚本兜底 |
| 元素引用能力收口 | P1 | 完整支持 `elementRefVar` 与 `elementOrder` 的组合语义 | 选择器类步骤可稳定复用前置元素结果并按顺序取目标元素 |
| 中频页面操作补齐 | P1 | 补齐 `goBack` 与 `closeOtherPages` | 页面流编排不再依赖 `executeJs` 或人工变通 |
| 0.0.7 能力不回归 | P0 | 保持断点、单步、预览、子流程与数据处理能力稳定 | 0.0.7 核心联调与回归继续通过 |

## 2. 缺口来源

- 来源一：`feedback/0.0.7.md` 明确指出编辑器视觉质量、调试面板信息组织、滚动行为、暗色主题、运行入口语义与调试浏览器生命周期存在明显体验问题。
- 来源二：`report/unimplemented-features.md` 显示当前仍缺少若干高频步骤与元素引用增强能力，其中 `keyboardPress`、`keyboardHotkey`、`textExtract` 属于近期最值得补齐的基础能力。
- 版本判断：0.0.8 不再继续横向铺大功能面，而是优先做一次**查缺补漏**，把最影响使用连续性的短板补平。

## 3. 本版范围

### 3.1 体验收口

- 左侧步骤库重做视觉层次：统一图标尺寸、统一绘制风格、减弱底色干扰、强化分类标题。
- 右侧 `RunPanel` 重做信息架构：默认只保留基础信息与调试预览，详细上下文收进展开区。
- 运行信息改为用户可读名称优先，避免直接暴露 `node_xxx` 一类内部标识。
- 支持从调试面板 hover 或点击步骤时联动画布高亮当前节点。
- 画布编辑页去除页面级总滚动条，只保留左右栏局部滚动和画布自身平移缩放。
- 节点配置项补齐提示图标与悬浮信息，降低首次配置门槛。
- 暗色主题统一颜色 token，修复面板、浮层、标签和文本对比度问题。

### 3.2 运行语义修正

- 首页或列表页点击“运行”后，跳转至编辑页时应自动完成本次运行启动，而不是只完成导航。
- 调试运行默认采用“执行结束后保留浏览器”的策略，直到用户显式关闭调试会话或浏览器。
- 普通运行与调试运行的入口提示、状态反馈和结束语义要清晰区分。

### 3.3 高频能力补洞

- 新增 `keyboardPress`：单键输入，覆盖 Enter、Tab、Escape、Delete、方向键等常用按键。
- 新增 `keyboardHotkey`：组合键输入，覆盖 Control/Meta/Shift/Alt 组合场景。
- 新增 `textExtract`：基于正则从文本中提取目标内容，并写回变量。
- 完整支持 `elementRefVar + elementOrder` 组合能力，允许步骤直接消费前置步骤产出的元素集合。
- 新增 `goBack` 与 `closeOtherPages`，补齐常见页面流控制动作。

## 4. 暂不纳入 0.0.8 的缺口

- 文件与表格能力：`saveData`、`saveExcel`、`importExcel`。
- 系统与外部数据能力：`getClipboardText`、`extractActiveElement`、`googleSheet`、`getEmail`。
- 网络监听能力：`listenRequestTrigger`、`listenRequestResult`、`stopPageListen`。
- 高级调试能力：条件断点、表达式断点、时间旅行调试、预览画面远程操控。
- 模板生态能力：模板市场、远程模板仓库、计划任务。
- 账号与权限体系：登录注册、多租户、模板共享协作。
- 通用效率增强：自动保存、节点自动布局、模板搜索、标签分组、批量删除、模板克隆。

> 说明：以上能力仍属于“当前缺口”，但不进入 0.0.8 主交付，避免版本目标从“查缺补漏”失控成“大而全补完”。

## 5. 核心方案摘要

### 5.1 编辑器体验方案

- 以现有 `NodeConfigPanel`、`RunPanel` 与编辑页三栏布局为基础收口，不新增第二套编辑器 UI。
- 视觉改造优先调整间距、层次、图标系统、标题样式与暗色 token，而不是堆叠更多装饰性元素。
- 通过滚动容器边界梳理，确保页面本体不滚动，左右栏各自独立滚动，画布区域只负责拖拽与缩放。

### 5.2 调试工作台方案

- `RunPanel` 默认只展示：运行状态、当前步骤、失败定位、调试预览与常用按钮。
- `contextId`、`stepPath`、变量原文、事件流、日志列表等技术细节收纳进“详情”区域。
- 节点显示名称统一使用步骤标题、步骤类型中文名或节点别名，内部 ID 仅在详情中保留。
- 调试运行结束后保留浏览器与预览会话摘要，并提供显式“关闭调试”入口。

### 5.3 高频步骤补齐方案

- 键盘步骤沿用现有步骤模型、保存加载与导入导出链路，不引入特殊执行分支。
- `textExtract` 只先解决高频正则提取，不扩展成通用文本处理 DSL。
- `elementRefVar` 与 `elementOrder` 作为选择器类步骤的统一能力补齐，避免每个节点单独定制一套引用逻辑。

## 6. 分阶段推进

### Phase A：文档与范围冻结（P0）

- 完成 `plan/0.0.8/plan.md`
- 完成 `plan/0.0.8/requirements.md`
- 明确纳入项、延期项与验收口径

### Phase B：前端体验收口（P0）

- 重做左侧步骤库视觉层次
- 重构 `RunPanel` 信息架构与按钮区
- 去除编辑页总滚动条并修复暗色样式
- 为配置项补齐 tips 与说明文案

### Phase C：运行语义修正（P0）

- 打通“列表运行 -> 编辑页自动启动”的跨页意图传递
- 调整调试运行结束后的浏览器保留策略
- 补齐前端文案、状态提示和关闭动作

### Phase D：后端步骤补齐（P0）

- 实现 `keyboardPress`、`keyboardHotkey`、`textExtract`
- 实现 `goBack`、`closeOtherPages`
- 完整补齐 `elementRefVar + elementOrder` 的执行语义

### Phase E：前端步骤配置与联调（P0）

- 步骤库新增上述步骤入口
- 节点配置面板新增配置项、tips、校验与默认值
- 保存加载、导入导出、画布渲染与调试定位全部接通

### Phase F：测试与回归（P0）

- 覆盖编辑器布局、暗色主题、运行跳转语义与调试保留浏览器场景
- 覆盖新增步骤与元素引用增强能力
- 对 0.0.7 调试链路、子流程和数据处理能力做回归验证

## 7. 主要风险

| 风险 | 影响 | 缓解策略 |
|---|---|---|
| 体验优化过于发散 | 版本容易演变成无边界的 UI 重做 | 只修复三栏布局、调试面板和暗色主题，不扩展全站视觉改版 |
| 运行入口语义跨页耦合 | 可能引入重复启动或误启动 | 以一次性运行意图参数或状态标记实现，并增加幂等保护 |
| 调试浏览器保留后资源未释放 | 长时间占用浏览器与调试会话 | 增加显式关闭入口、超时清理与状态提示 |
| 元素引用增强影响多个步骤 | 易引入旧步骤行为回归 | 以统一解析层实现，并做选择器类步骤回归测试 |
| 新增步骤多端联动较长 | 前后端模型、校验与文档容易不同步 | 先冻结步骤 schema，再进入前后端实现 |

## 9. 版本完成判定

1. 编辑页在亮色与暗色下都无明显样式错乱，且不存在页面级总滚动条。
2. `RunPanel` 默认信息密度明显下降，节点名称对用户可读，并可定位或高亮对应节点。
3. 从模板列表点击运行后，进入编辑页即可自动发起对应运行。
4. 调试运行完成后浏览器默认保留，用户可继续查看或手动关闭调试会话。
5. `keyboardPress`、`keyboardHotkey`、`textExtract`、`goBack`、`closeOtherPages` 可稳定运行。
6. `elementRefVar + elementOrder` 可在主要选择器类步骤中稳定工作。
7. 0.0.7 断点、单步、预览、子流程与数据处理能力不回归。

总结：0.0.8 的目标不是继续扩张产品边界，而是把最影响实际使用体验和高频编排效率的短板补齐，让系统从“功能已多”走向“真正顺手”。
