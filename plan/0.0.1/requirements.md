## 1. 目标与边界

### 1.1 版本目标（0.0.1）
- 用户能在「模板列表」管理工作流模板（创建/编辑/删除/导入/导出）。
- 用户能在「画布编辑」通过拖拽节点+连线+配置参数，保存为模板，并能发起一次执行。
- 执行过程中能在前端看到“正在执行到哪一步/是否成功/失败原因（最小可用）”。

解释：0.0.1 关注“可用闭环”，而非“功能齐全”。能完成一次可演示的流程，即达成目标。

### 1.2 目标用户与使用场景
- 目标用户：个人用户、运营/数据岗位、需要重复网页操作的非开发者。
- 核心场景：录入表单、抓取信息、定时检查页面内容（0.0.1 先不做定时）。

补充说明：0.0.1 更重视“低门槛可视化编排”，因此减少复杂条件与循环。

### 1.3 MVP 假设（强建议先这样落地）
- **单机/单用户**：默认本地运行（后端执行器与前端在同一环境）。
- **不引入账号体系**：0.0.1 不做登录/注册（见第 4 节）。
- **模板存储**：允许先做本地存储或服务端存储，但对产品呈现为“能保存与读取”。

这样做的好处是：减少部署与权限复杂度，把时间集中在“流程编排 + 执行 + 监控”的核心价值上。

## 2. 页面一：模板列表（Workflow Templates）

> 这是用户的入口页，负责“管理”和“进入编辑/运行”。

### 2.1 列表展示信息（每条模板）
- 模板名称
- 最近更新时间
- 简要描述（可选）
- 节点数量（可选，便于判断复杂度）
- 最近一次运行状态（可选：成功/失败/未运行）

提示：列表项应尽量“信息密度高但不臃肿”，以支持快速筛选与判断模板可用性。

### 2.2 核心功能（0.0.1 必做）
1. 新建模板
   - 点击“新建”进入编辑页
   - 可选择“空白模板”
2. 打开模板（进入编辑页）
   - 点击列表项/编辑按钮进入画布编辑
3. 重命名与描述
   - 允许在列表页快速改名，或进入编辑页改名
4. 删除模板
   - 二次确认（避免误删）
5. 导入模板（JSON）
   - 从本地选择文件导入
   - 导入失败时提示原因（格式不对/版本不兼容）
6. 导出模板（JSON）
   - 下载单个模板的 JSON

### 2.3 建议功能（0.0.1 可选 / 0.0.2+）
- 复制/克隆模板（快速复用）
- 搜索（按名称）
- 标签/分组
- 批量删除
- 运行历史入口（跳转到运行详情页）

### 2.4 关键交互规则
- 任何会导致数据丢失的操作（删除、覆盖导入）必须二次确认。
- 导入的模板若 schemaVersion 高于当前支持版本，应给出明确提示与建议（例如“请升级系统”）。

意图说明：0.0.1 阶段以“避免误删与误覆盖”为第一优先级。

## 3. 页面二：画布编辑（Canvas Editor）

> 这是产品核心：编排流程 + 配置节点 + 运行与监控。

### 3.1 页面结构（建议布局，不限定实现）
- 中央：画布（ReactFlow）
- 侧边：
   - 节点库（可拖拽添加）
   - 节点属性面板（选中节点时显示）
- 顶部/工具栏：保存、运行、停止、导入/导出
- 底部/右侧：运行日志/事件列表（最小可用的监控区）

说明：布局仅用于指导功能区划分，可根据技术栈调整。

### 3.2 节点与连线能力（0.0.1 必做）
1. 节点添加
   - 从节点库拖拽到画布
   - 或点击添加（可选）
2. 节点移动
   - 拖动节点位置，画布实时刷新
3. 节点删除
   - 选中后删除（按钮或快捷键）
4. 节点连线
   - 从源节点输出点连到目标节点输入点
   - 基础规则：一条主线顺序执行（0.0.1 可先限制为“线性流程”或“单入口单出口”）

   补充：线性流程的限制是为了让运行引擎与校验逻辑更容易实现，后续版本可扩展为分支与循环。

### 3.3 节点配置（0.0.1 必做）
- 选中节点后，在属性面板配置该节点参数
- 配置项应提供：
   - 必填/选填标识
   - 基础校验（空值、格式、范围）
   - 帮助文案（例如 selector 示例）

意图说明：此处强调“配置可理解”，而非“参数尽量多”。

#### 3.3.1 0.0.1 建议支持的节点类型（最小集合）
- 打开网页（openUrl）：url
- 点击（click）：selector
- 输入（type）：selector + text
- 等待（waitFor）：selector 或 waitMs（二选一）
- 提取（extract）：selector + 目标字段名（as） + 提取类型（text/attribute）

> 说明：循环/条件属于第二阶段复杂度，0.0.1 可先不纳入，或做“只支持非常简单的配置”。

### 3.4 保存与版本（0.0.1 必做）
- 保存：将当前画布保存到模板
- 离开提示：未保存时离开页面要提示
- 自动保存（0.0.1 可选）：间隔保存/变更即保存（需要明确提示用户当前保存状态）

补充：建议在工具栏明确展示“已保存/未保存”状态，降低误操作风险。

### 3.5 导入/导出（0.0.1 必做）
- 编辑页也应支持导入/导出
- 导入：覆盖当前画布 or 作为新模板（建议弹窗选择）
- 导出：导出当前模板

建议：导入失败需给出原因（格式错误/版本不兼容），避免“无响应”的误解。

### 3.6 运行与监控（0.0.1 必做）
1. 运行（Start Run）
   - 在编辑页直接点击“运行”
   - 运行前校验：
      - 必填参数是否完整
      - 流程是否可执行（至少存在入口与顺序）
2. 停止/取消（Cancel）
   - 运行中可点击“停止”
3. 运行反馈（最小可用）
   - 显示当前执行节点（高亮）
   - 事件流：节点开始/成功/失败
   - 失败信息：错误摘要（例如超时/找不到元素）

   补充：监控区的目标是“可解释当前进度”，不要求完整日志系统。

### 3.7 体验增强（0.0.1 可选 / 0.0.2+）
- 撤销/重做
- 节点对齐/自动布局
- 运行参数面板（headless、浏览器类型、超时）
- 截图/保存 artifact（失败时截图）
- 变量面板：查看提取结果（例如 extract 产出的变量）

## 4. 是否需要其他页面？（结论 + 取舍）

### 4.1 登录/注册：0.0.1 不建议做
**不做的理由（适用于单机/毕业设计原型）**
- 账号体系会引入用户、权限、会话、安全等大量非核心工作。
- 0.0.1 的价值验证在“画布编排 + 执行稳定 + 监控可用”。

**什么情况下需要做**
- 你明确要“多用户、云端部署、模板隔离、权限管理”。

**折中方案（推荐）**
- 0.0.1 不做登录。
- 后续如果要云化：0.1.0 再引入登录与多租户。

### 4.2 设置页：0.0.1 可不单独成页
如果确实需要配置（例如默认浏览器、headless、代理、超时），0.0.1 可以先放在编辑页的“运行参数”区域，避免增加页面数量。

### 4.3 运行历史/运行详情页：0.0.1 可选
- 若监控面板已经在编辑页满足展示“本次运行”即可，运行历史可以推迟。
- 若你希望可复现与答辩展示更强：可以加一个轻量的“运行详情”页面（显示事件/日志/结果）。

## 5. 0.0.1 验收标准（建议）
- 能创建模板并在列表中看到
- 能在编辑页完成：放置 3-5 个节点、连线、配置、保存
- 能点击运行并让浏览器执行至少一个可复现流程（例如打开 example.com 并提取标题）
- 前端能看到节点级执行状态（开始/成功/失败）与错误提示

说明：若以上全部满足，即可认为 0.0.1 达成“可演示、可答辩”的最小闭环。

总结：本需求文档覆盖 0.0.1 的目标、页面与验收标准，便于对齐范围与优先级。
