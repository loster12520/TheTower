# 0.1.0 前端实施文档（编辑器体验补完 + 高级调试工作台升级 + 平台入口扩展）

导语：本文档用于拆分 0.1.0 前端工作，目标是在保持当前首页、编辑器、运行面板和调试工作台信息结构稳定的前提下，把剩余体验能力和平台化入口系统性补齐。

## 1. 实施目标与边界

- 目标：让 0.1.0 的体验增强和高级调试能力落到清晰的页面结构中，而不是靠零散弹窗拼接。
- 目标：保证新入口与现有模板管理、编辑器和调试工作流保持一致语义。
- 目标：为后续 0.1.0 回归测试提供稳定选择器和交互路径。
- 边界：本文件关注页面结构、状态流和交互主线，不下沉到具体组件内部实现。

## 2. 前端主线

| 模块 | 0.1.0 关注点 |
|---|---|
| 首页模板管理 | 搜索、标签/分组、批量选择、批量删除、克隆 |
| 编辑器页面 | 自动保存、自动布局、运行参数面板、协作提示 |
| 调试工作台 | 条件断点、时间旅行、远程操控入口 |
| 设置与平台入口 | 调度配置、账户与权限入口 |
| 模板市场页面 | 浏览、导入、发布和来源展示 |

## 3. 页面实施建议

### 3.1 首页模板管理

- 搜索框需要与列表刷新、分页和筛选共存，不应造成状态冲突。
- 标签或分组应进入卡片展示与筛选栏，而不是仅在详情里可见。
- 批量删除与克隆应有明确反馈和可测试的交互状态。

### 3.2 编辑器页面

- 自动保存状态需要放在用户可持续感知的位置，避免无提示后台保存。
- 自动布局入口应与画布工具栏语义一致，并对成功或失败给出反馈。
- 运行参数面板应统一服务普通运行与调试运行，避免两个入口字段漂移。

### 3.3 调试工作台

- 条件断点需要在节点层与调试面板层都有可见反馈。
- 时间旅行应至少提供时间轴、快照列表或步骤历史中的一种稳定视图。
- 远程操控操作要和预览区域绑定，并明确当前是否允许点击、输入或滚动。

### 3.4 平台化入口

- 调度、模板市场、账户权限和协作入口需有清晰导航归属。

## 4. 状态管理要求

- 自动保存、批量操作、运行参数和调试时间轴应有独立状态，避免互相污染。
- 高级调试相关状态要区分“当前实时帧”和“历史回放帧”。
- 协作编辑要区分本地未提交改动、远端同步改动和冲突提示。

## 5. 测试重点

1. 自动保存、搜索、标签、克隆、自动布局、批量删除的主交互稳定可回归。
2. 运行参数面板在普通运行与调试运行下字段一致、默认值一致、校验一致。
3. 调试工作台能稳定展示条件断点命中、时间轴切换和远程操控结果。
4. 模板市场、调度、权限和协作入口至少具备端到端最小演示路径。

## 6. 交付物

- 首页、编辑器、调试工作台和相关新页面的实现。
- 前端 E2E 用例与必要的 mock 数据补充。
- `docs/user-guide.md` 的 0.1.0 功能章节。
- `report/0.1.0/tech.md` 中的前端实现记录。

## 7. 实施顺序

1. 先完成首页模板管理与编辑器体验增强。
2. 再完成运行参数面板与高级调试工作台升级。
3. 再完成数据与文件节点配置与模板市场入口。
4. 最后完成调度、权限与协作首版入口。

总结：0.1.0 前端的核心不是增加更多按钮，而是把新能力放进稳定、顺手、可回归的页面结构中。
