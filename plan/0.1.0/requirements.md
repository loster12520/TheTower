## 范围与非目标

- 范围：把当前未完成清单中的所有条目全部纳入 0.1.0。
- 范围：同时覆盖真实云部署验收、编辑器体验增强、高级调试、数据与外部集成、产品化能力。
- 范围：以“最终都要实现完成”为原则，不再为本版保留新的延期项。
- 非目标：不新增与未完成清单无关的大规模新主题。
- 非目标：不因为局部实现困难而把已纳入 0.1.0 的条目再次下放到后续版本。

## 承接基线

- 0.0.9 已完成本地工程化交付闭环，已有用户文档、API 文档、部署手册、部署样例文件和云部署验收模板。
- 0.0.9 已完成本地指标验收，现有基线包括：后端主链路 17/17、三浏览器兼容 17/17、mock 28/28、real 17/17、50 节点性能测量、成功率 100%。
- 0.1.0 不再围绕“证明可用”组织版本，而是围绕“补齐剩余能力并形成产品初版”组织版本。

## 1. 云部署实机验收

- 必须按 `docs/deployment.md` 与 `docs/deploy/linux/*` 在真实云服务器完成部署。
- 必须填写 `report/0.0.9/deployment-validation.md` 或迁移后的 0.1.0 验收记录。
- 必须完成健康检查、首页访问、模板管理、普通运行、调试运行、事件流、产物目录与日志写入验证。
- 必须把云部署结果回填到测试报告和版本总结。

## 2. 编辑器体验增强

### 2.1 自动保存

- 编辑页需要支持自动保存或定时保存。
- 自动保存必须可感知，至少有状态提示、最近保存时间或失败提示。
- 自动保存不能破坏现有手动保存语义。

### 2.2 模板搜索

- 首页模板列表需要支持按名称快速过滤。
- 搜索结果需与分页、排序或列表刷新兼容。
- 搜索为空时要给出明确空状态，而不是静默无结果。

### 2.3 模板标签与分组

- 模板需要支持标签、分类或分组中的至少一种结构化管理方式。
- 标签或分组需要参与展示与筛选，不只是静态字段。

### 2.4 模板复制与克隆

- 用户需要能从已有模板快速生成副本。
- 克隆后的模板默认应生成新 ID，并保留步骤、画布结构和大部分元数据。

### 2.5 节点自动布局

- 编辑器需要提供自动布局能力，至少支持线性主流程和基础分支场景。
- 自动布局不能破坏节点配置与连线关系。

### 2.6 批量删除模板

- 首页模板管理需要支持多选与批量删除。
- 批量删除需要二次确认和失败反馈。

### 2.7 运行参数面板增强

- 运行前需要提供浏览器类型、headless、超时等参数配置入口。
- 参数需要能在普通运行与调试运行之间保持一致语义。
- 参数值需要有默认值、校验规则和回显机制。

## 3. 高级调试能力

### 3.1 条件断点

- 断点需要支持表达式条件、变量条件或命中次数条件中的一种或多种。
- 断点命中时需给出命中原因，而不是只显示“已暂停”。

### 3.2 时间旅行调试

- 调试工作台需要支持执行历史回放或状态回溯。
- 至少应能查看关键步骤、变量快照和运行轨迹的历史状态。

### 3.3 预览远程操控

- 调试预览中需要支持至少基础点击、输入或页面交互。
- 远程操控必须与当前调试会话上下文一致，并有权限边界与状态提示。

## 4. 数据与文件集成

- 需要实现 `saveData`、`saveExcel`、`importExcel`、`getClipboardText`、`extractActiveElement`。
- 文件类节点必须明确输入路径、输出路径、失败反馈和产物落盘位置。
- Excel 类节点必须至少支持最小可用的读写能力，而不是只定义配置表单。

## 5. 网络与第三方平台

- 需要实现 `listenRequestTrigger`、`listenRequestResult`、`stopPageListen`。
- 需要补齐 `googleSheet`、`getEmail`、2Captcha 或同类打码平台接入、OpenAI 或 LLM 集成。
- 第三方平台能力必须考虑凭证配置、错误反馈、限流或网络失败处理。
- 所有第三方能力都需要有 mock 或降级策略，避免测试完全依赖外部网络环境。

## 6. 产品化能力首版

- 计划任务：支持定时触发流程运行。
- 模板市场：支持模板分发、展示或复用入口。
- 多用户与权限：支持登录、权限隔离和基础多租户模型。
- 协作编辑：支持模板共享与多人协作首版。

> 说明：这里的“首版”不代表只做界面入口，而是至少形成完整可演示闭环。

## 前后端实现约束

### 前端约束

- 所有新增入口必须和现有编辑器、首页、运行面板和调试工作台保持一致视觉语义。
- 体验增强功能不能通过大量临时弹窗堆砌实现，应尽量融入现有工作流。
- 高级调试能力必须考虑交互复杂度，避免界面信息过载。

### 后端约束

- 所有新增节点必须进入统一注册、校验、执行、错误码与持久化链路。
- 第三方平台能力必须支持配置隔离与错误回传。
- 调试增强能力不能破坏现有运行主链路和 WebSocket 协议稳定性。

### 协议约束

- 新功能需要同步补充 REST、WebSocket、错误码和用户文档。
- 不允许出现“UI 可点、协议未定义”或“协议已加、文档缺失”的状态。

## 测试与验收口径

1. 云部署验收。
   - 在真实云服务器按部署手册完成完整部署。
   - 验收点：系统可访问、可运行、可调试、可写日志与产物。

2. 体验增强验收。
   - 对自动保存、搜索、标签、克隆、自动布局、批量删除、运行参数面板逐项回归。
   - 验收点：功能真实可用，且不回归当前主链路。

3. 高级调试验收。
   - 对条件断点、时间旅行、远程操控逐项验证。
   - 验收点：能支撑复杂故障定位，而不是仅有演示入口。

4. 数据与集成节点验收。
   - 为每个新增节点准备最小可执行场景。
   - 验收点：节点能真实执行、输出可见、失败可解释。

5. 产品化能力验收。
   - 对计划任务、模板市场、多用户权限、协作编辑逐项验证。
   - 验收点：具备可演示闭环，不是纯静态页面。

## 阶段拆分建议

1. 先完成云部署验收与编辑器体验增强，因为这两类能力最直接改善交付与使用效率。
2. 再完成高级调试，因为其涉及前后端状态机与交互联动。
3. 再推进数据与第三方集成，因为其外部依赖更多。
4. 最后完成产品化能力首版，因为它跨模板、运行、权限和协作多个领域。

总结：0.1.0 的需求原则不是“挑几个最容易的先做”，而是把当前未完成清单中的全部能力正式纳入版本并最终全部实现完成。
