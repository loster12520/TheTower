# 0.0.7 版本目标（调试深化 + 流程复用 + 数据处理补齐）

导语：本版本聚焦把 0.0.6 的“可看见调试”升级为“可暂停、可单步、可查变量”的调试闭环，并同步补齐子流程复用与常用数据处理步骤，形成更完整的工作流工程化能力。

## 1. 版本目标

| 目标项 | 优先级 | 说明 | 验收信号 |
|---|---:|---|---|
| 调试控制深化 | P0 | 支持断点、暂停、继续、单步与稳定的调试状态机 | 调试运行可命中断点并停在当前节点 |
| 变量检查器 | P0 | 运行中可查看当前变量快照、页面和上下文信息 | 运行面板可展示最新变量与调试上下文 |
| 子流程复用 | P0 | 支持 `callWorkflow` 调用现有模板并传递参数 | 一个模板可引用另一个模板执行 |
| 数据处理步骤 | P0 | 支持 `convertJson`、`extractKey`、`randomGet` 等高频数据操作 | 无需依赖 `executeJs` 即可完成常见数据转换 |
| 0.0.6 不回归 | P0 | 保持近实时预览、全屏调试、左右端口与编辑器能力稳定 | 0.0.6 核心联调与回归继续通过 |

## 2. 版本边界（不做）

- 不在本版实现条件断点、表达式断点和时间旅行调试。
- 不做预览画面内的远程点击、键盘输入与浏览器接管。
- 不做跨项目模板市场、跨环境模板仓库与多人协作。
- 不继续扩展大批第三方平台步骤，优先完成通用调试与数据能力。

## 3. 核心方案摘要

### 3.1 调试方案

- 在现有 run 事件流基础上增加断点命中、暂停、继续、单步与变量快照事件。
- 调试状态机保持与默认运行模式共用同一 run 生命周期，不另造第二套执行语义。
- 变量快照优先在暂停点、步骤完成点和关键状态变更时推送，不做逐帧高频全量同步。

### 3.2 流程复用方案

- 新增 `callWorkflow` 步骤，允许模板在运行时调用另一模板。
- 0.0.7 先支持同系统模板引用、显式参数映射和循环引用保护。
- 子流程调用后的事件路径、变量作用域和错误传播要可观测、可追踪。

### 3.3 数据处理方案

- 优先交付高频、低歧义的数据步骤：`convertJson`、`extractKey`、`randomGet`。
- 统一这些步骤的输入校验、空值行为、错误码和输出变量写回策略。
- 复杂整形仍允许由 `executeJs` 兜底，避免 0.0.7 一次性做成通用脚本平台。

## 4. 分阶段推进

### Phase A：文档与协议定义（P0）

- 完成 `plan/0.0.7/plan.md`
- 完成 `plan/0.0.7/requirements.md`
- 完成 `plan/0.0.7/steps/{api.md,backend-plan.md,frontend-plan.md}`
- 完成 `report/0.0.7/{tech.md,test.md}` 模板

### Phase B：调试协议与步骤模型（P0）

- 定义断点、暂停、继续、单步、变量快照协议
- 扩展模板 schema 与步骤模型，纳入 `callWorkflow` 与数据处理步骤
- 明确错误码、变量输入输出与路径语义

### Phase C：后端调试状态机（P0）

- 增加 run 级调试控制上下文
- 实现断点命中、暂停、继续、单步
- 输出稳定的变量快照与当前 `stepPath`

### Phase D：后端子流程复用与数据步骤（P0）

- 实现 `callWorkflow`
- 实现 `convertJson`、`extractKey`、`randomGet`
- 增加循环引用保护与变量作用域约束

### Phase E：前端调试工作台与步骤配置（P0）

- 运行面板增加断点、变量检查器与单步控制
- 编辑器增加节点断点入口与命中高亮
- 配置面板与步骤库补齐 `callWorkflow` 和数据步骤

### Phase F：测试与回归（P0）

- 后端单测与黑盒脚本覆盖调试控制与新步骤
- 前端 mock 与真实联调覆盖断点、变量、子流程复用与数据步骤
- 0.0.6 调试预览与编辑器体验全量回归

## 5. 主要风险

| 风险 | 影响 | 缓解策略 |
|---|---|---|
| 调试暂停状态机与既有 run 生命周期耦合过深 | 容易引入取消、重启与关闭调试时的竞态 | 先在模型层明确定义状态转换，再实现服务层控制 |
| `callWorkflow` 循环引用或递归过深 | 导致 run 卡死或堆栈爆炸 | 保存与运行两侧都做递归检测和深度限制 |
| 变量快照高频推送负载过大 | WebSocket 压力升高，前端状态管理变重 | 只在断点、步骤结束和显式请求时推送快照 |
| 数据处理步骤语义不清 | 前后端配置与执行结果不一致 | 文档先定义输入输出和边界行为，再进入实现 |
| 0.0.7 体量高于 0.0.6 | 容易出现中途收口困难 | 以调试深化为主轴，必要时把 `callWorkflow` 收敛为 0.0.7.x |

## 7. 版本完成判定

1. 调试运行可命中断点并暂停。
2. 运行面板可继续、单步并查看变量快照。
3. `callWorkflow` 可稳定调用目标模板并回传执行结果。
4. `convertJson`、`extractKey`、`randomGet` 可完成高频数据处理闭环。
5. 0.0.6 的预览、全屏、浏览器调试入口、左右端口和编辑器能力不回归。

总结：0.0.7 的重点不是单纯补几个步骤，而是把调试、复用与数据三条主线合并成真正可工程化的工作流能力。
