## 范围与非目标

- 范围：调试运行支持断点、暂停、继续、单步与变量快照展示。
- 范围：工作流新增 `callWorkflow`，支持同系统模板复用与显式参数映射。
- 范围：新增 `convertJson`、`extractKey`、`randomGet` 等高频数据处理步骤。
- 范围：本版测试重点覆盖调试控制、变量检查器、流程复用与数据步骤，并要求 0.0.6 全量回归。
- 非目标：不在本版实现条件断点、表达式断点、时间旅行调试。
- 非目标：不做预览画面中的远程操控。
- 非目标：不做跨系统模板市场、多人协作和更大规模第三方平台步骤扩展。

## 承接基线（来自 0.0.6）

- 0.0.6 已完成：近实时调试预览、全屏查看、宿主机浏览器调试入口。
- 0.0.6 已完成：左右端口、无抖动选中态、复制剪切粘贴、撤销重做与自动连线。
- 0.0.7 不重做调试预览链路，而是在此基础上补足**调试控制**、**模板复用**与**数据处理**。

> 说明：0.0.7 的核心不是“又加一些表单”，而是把 **断点排错、流程复用、数据转换** 三条常用主线做成默认能力。

## 0.0.7 调试深化

### 1. 断点与暂停

- 节点应支持显式设置或取消断点。
- 调试运行命中断点后，run 进入暂停态，当前节点应保持可见且不继续自动前进。
- 断点优先支持节点级断点，不在本版支持表达式断点。
- 命中断点后仍保留 0.0.6 的调试预览与页面上下文显示。

### 2. 继续与单步

- 暂停后应支持“继续运行”与“单步执行下一节点”。
- 单步的最小粒度为“一个步骤执行单元”，不要求 step 内部指令级调试。
- 若当前 run 已结束、取消或报错，继续与单步入口应禁用并提示原因。

### 3. 变量检查器

- 运行面板应展示当前变量快照。
- 最少应显示：变量名、变量值摘要、当前 `stepPath`、当前 `pageAlias`、当前 `contextId`。
- 对较大的对象和数组可做摘要展示，但要允许查看原始文本或 JSON。
- 变量快照的更新时间要明确可见，避免误解为实时逐字符同步。

### 4. 调试状态与运行状态一致性

- 调试暂停、继续、单步必须与同一个 run 生命周期绑定。
- 调试关闭、run 取消、run 重启时，断点和暂停态要有明确清理规则。
- 普通运行模式不应因为断点能力而产生额外开销或状态污染。

## 0.0.7 流程复用

### 1. callWorkflow 子流程调用

- 工作流步骤库新增 `callWorkflow`。
- 该步骤允许引用另一个已存在模板，并在运行时执行目标模板。
- 父流程中的执行事件应能体现当前位于哪一个被调用模板，避免路径不可读。

### 2. 参数映射与结果写回

- `callWorkflow` 至少支持显式入参映射。
- 子流程执行结束后，应支持把结果写回指定变量。
- 若被调用模板执行失败，父流程应能收到明确错误并定位失败路径。

### 3. 循环引用与嵌套限制

- 保存模板时应尽可能发现直接或间接循环引用。
- 运行时仍需防御递归过深或非法引用，避免依赖前端校验。
- 0.0.7 可设置最大嵌套层数，超出时返回结构化错误。

## 0.0.7 数据处理步骤

### 1. convertJson

- 输入支持字符串或对象。
- 目标是完成 JSON 字符串与对象之间的规范转换。
- 非法 JSON 应返回明确错误，而不是静默得到 `null`。

### 2. extractKey

- 输入支持对象或数组中的对象。
- 至少支持通过 keyPath 提取值，如 `data.items[0].title`。
- key 不存在时应允许配置为报错或返回空值，但 0.0.7 文档中必须先固定一种默认行为。

### 3. randomGet

- 输入支持数组。
- 输出为数组中一个随机元素，并支持写回指定变量。
- 空数组时的行为必须有明确定义，不能依赖实现细节。

## 前后端实现约束

### 前端约束

- 调试控制优先在现有 `RunPanel` 基础上增强，不新增独立调试页面。
- 断点开关要与编辑器节点状态联动，命中时能快速定位节点。
- `callWorkflow` 与数据步骤必须完整接入步骤库、节点配置、保存加载、导入导出与校验流程。

### 后端约束

- 调试状态机必须与既有 run 生命周期共用同一套模型，不允许形成“双 run 语义”。
- `callWorkflow` 的循环引用保护不能只依赖前端；保存和运行两侧都要兜底。
- 数据处理步骤的错误码、空值行为与输出写回策略必须稳定，不依赖前端猜测。

### 协议约束

- 调试事件在 0.0.6 基础上新增，不替换既有 `DEBUG_FRAME` 等协议。
- 变量快照和断点状态应以新增字段或事件扩展，不破坏 0.0.6 已完成的真实联调逻辑。
- `stepPath`、`outputs`、`artifacts` 仍是核心对齐字段，`callWorkflow` 只扩展其层级语义。

## 测试与验收口径

1. 断点暂停闭环
   - 设置节点断点并以调试模式运行模板。
   - 验收点：run 命中断点后暂停，当前节点、预览与变量快照可见。

2. 单步恢复闭环
   - 在暂停态点击单步和继续。
   - 验收点：单步只推进一个步骤，继续后 run 能恢复完整执行。

3. 变量检查器闭环
   - 执行带提取、赋值和循环的模板。
   - 验收点：变量面板能看到关键变量、当前路径和上下文信息。

4. `callWorkflow` 闭环
   - 父模板调用子模板并传参。
   - 验收点：子模板执行成功，父模板收到返回结果，失败时路径可定位。

5. 数据处理闭环
   - 使用 `convertJson`、`extractKey`、`randomGet` 处理输入数据。
   - 验收点：输出变量符合预期，异常输入返回稳定错误。

6. 回归闭环
   - 执行 0.0.6 mock 与真实联调回归。
   - 验收点：调试预览、全屏、浏览器调试入口、左右端口和编辑器能力不回归。

## 延期项（明确不纳入 0.0.7）

| 类别 | 延期项 | 延期原因 |
|---|---|---|
| 高级调试 | 条件断点、表达式断点、时间旅行调试 | 状态机与 UI 成本明显超出本版范围 |
| 远程控制 | 预览画面内直接点击和输入接管 | 坐标映射与安全边界复杂度高 |
| 模板生态 | 跨项目模板市场、远程模板仓库 | 需要更重的权限和版本治理设计 |
| 步骤扩展 | 更大规模第三方平台步骤 | 本版优先保证通用能力和工程化质量 |

总结：0.0.7 的交付标准是“调试时能停能看能继续、编排时能复用、数据处理时少写脚本”，先把这些高频工程化能力做透，再继续扩更多步骤家族。
