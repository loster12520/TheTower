# 0.0.7 后端实施文档（调试状态机 + callWorkflow + 数据处理步骤）

导语：本文档用于指导 0.0.7 后端实现，重点解决调试暂停与单步控制、模板复用执行以及常用数据处理步骤落地。

## 1. 实施目标与边界

- 目标：在 0.0.6 调试会话基础上增加断点、暂停、继续、单步与变量快照。
- 目标：实现 `callWorkflow`，支持同系统模板复用与参数映射。
- 目标：实现 `convertJson`、`extractKey`、`randomGet` 等数据步骤。
- 边界：不在本版实现条件断点、时间旅行调试与跨系统模板市场。

## 2. 后端改造主线

| 模块 | 当前现状 | 0.0.7 目标 |
|---|---|---|
| `RunService` | 已负责 run 生命周期、调试预览与调试会话管理 | 增加暂停态状态机、断点命中、继续/单步控制、变量快照管理 |
| `PlaywrightRunSession` | 已支持调试预览、page/context 管理与步骤执行 | 暴露稳定变量快照与暂停恢复所需上下文 |
| `TemplateService` | 已负责 schema 版本校验与模板保存 | 纳入 `callWorkflow` 与数据步骤 schema 校验 |
| `StepTreeSupport` | 已承接步骤解析与部分校验支持 | 承接递归路径拼接、循环引用检测和新步骤通用解析 |
| routes / WebSocket | 已支持 run 与调试基础接口 | 新增调试控制接口和变量快照事件 |

## 3. 模块拆分建议

### 3.1 `RunService` 负责调试状态机

- 维护 run 级断点集合、暂停态、继续与单步令牌。
- 在步骤执行前检查是否命中断点或 `pauseOnStart`。
- 暂停时发射断点事件与变量快照；恢复时发射继续或单步事件。
- 关闭、取消、重启时统一清理调试上下文，避免状态残留。

### 3.2 `PlaywrightRunSession` 负责上下文快照

- 提供当前变量、`pageAlias`、`contextId`、最近 `stepPath` 的统一快照接口。
- 保持调试预览采样与暂停恢复共存，不因暂停丢失当前页面信息。
- 若未来需要扩展更细粒度调试，应确保该类仍是唯一底层上下文来源。

### 3.3 `callWorkflow` 执行器

- 从模板仓库加载目标模板。
- 处理显式入参映射与结果写回。
- 拼接父子 `stepPath`，让错误与事件可追踪。
- 对循环引用、非法模板和过深嵌套返回结构化错误。

### 3.4 数据步骤执行器

- `convertJson`：对象与 JSON 字符串互转。
- `extractKey`：按 keyPath 提取对象或数组中的值。
- `randomGet`：从数组中随机取一个元素。
- 统一空值行为、异常包装和输出写回逻辑。

## 4. 公共能力要求

### 4.1 调试暂停与恢复

- 暂停态必须可等待用户控制，而不是忙轮询阻塞整个服务。
- 单步建议通过“只放行一个步骤执行单元”实现，避免复杂的内部指令级调试。
- 普通运行不进入暂停检测分支，保证 0.0.6 默认路径性能稳定。

### 4.2 变量快照

- 变量快照至少包含当前变量 Map、`stepPath`、`pageAlias`、`contextId` 和时间戳。
- 建议在断点命中、步骤成功、步骤失败前后更新，而不是每一帧都推送全量变量。
- 返回给前端时应考虑大对象摘要或截断策略，避免单条事件过大。

### 4.3 子流程复用

- 保存模板时先做静态循环引用校验；运行时仍需二次兜底。
- 子流程失败时要保留父路径和子路径，避免只看到内部错误而无法回到父步骤。
- 建议限制最大嵌套深度，防止错误模板拖垮运行。

## 5. 测试重点

1. 调试暂停、继续与单步的服务层单测。
2. 断点命中时变量快照与路径事件正确性。
3. `callWorkflow` 的参数传递、结果写回与错误传播。
4. `callWorkflow` 的循环引用、模板不存在和嵌套深度限制。
5. `convertJson`、`extractKey`、`randomGet` 的输入输出与异常边界。
6. 0.0.6 调试预览、关闭调试和默认运行模式不回归。

## 6. 实施顺序

1. 定义调试控制与变量快照模型
2. 扩 `RunService` 状态机与控制接口
3. 扩 `PlaywrightRunSession` 上下文快照能力
4. 实现 `callWorkflow`
5. 实现数据处理步骤
6. 补 WebSocket 事件与后端自动化测试

总结：0.0.7 后端的重点是把“调试看得到”推进到“调试停得住、复用跑得通、数据处理有默认能力”，而不是继续堆叠独立执行分支。
