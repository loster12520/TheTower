# 0.0.7 前端实施文档（调试工作台 + 断点交互 + 新步骤配置）

导语：本文档用于指导 0.0.7 前端实现，重点解决断点交互、变量检查器、子流程复用节点与数据处理步骤配置落地。

## 1. 实施目标与边界

- 目标：让运行面板升级为真正可控制的调试工作台。
- 目标：让编辑器支持节点断点设置、命中高亮与快速定位。
- 目标：让 `callWorkflow` 与数据处理步骤完整接入步骤库、表单配置和保存加载流程。
- 边界：不在本版新增独立调试页面，不重写画布整体架构。

## 2. 前端改造主线

| 模块 | 当前现状 | 0.0.7 目标 |
|---|---|---|
| `RunPanel` | 已支持预览、日志、事件与调试关闭入口 | 增加断点命中态、变量检查器、继续/单步控制 |
| `runStore` | 已维护调试 session、帧与事件 | 增加暂停态、断点信息、变量快照与控制动作 |
| `nodes` / `editorStore` | 已支持左右端口、编辑器历史与子流程编辑 | 增加节点断点标记、命中高亮与节点快速定位 |
| `stepRegistry` / `NodeConfigPanel` | 已覆盖 0.0.6 之前步骤 | 纳入 `callWorkflow` 与数据处理步骤的表单和说明 |
| `canvasConverter` / `validator` | 已支持控制流和 0.0.5/0.0.6 步骤 | 增加新步骤转换与配置校验 |

## 3. 调试工作台建议

### 3.1 运行面板布局

- 顶部：run 状态、当前 `stepPath`、当前页面与上下文。
- 中部：保留 0.0.6 预览卡片，并在旁侧增加断点控制区。
- 下部：变量检查器、outputs、artifacts、日志与事件流。

### 3.2 暂停与单步交互

- 命中断点后，运行面板应明确显示“已暂停”。
- 提供“继续运行”“单步执行”“关闭调试”按钮。
- 按钮状态要与 run 当前状态严格对应，避免在非暂停态误触。

### 3.3 变量检查器

- 变量检查器最少展示变量名和值摘要。
- 复杂对象建议支持折叠或 JSON 文本查看。
- 应同时展示快照时间、当前 `stepPath`、`pageAlias`、`contextId`。

## 4. 编辑器与步骤配置改造

### 4.1 节点断点交互

- 节点应支持设置断点的显式入口，如图标、菜单或快捷操作。
- 命中断点后，编辑器应能自动定位并高亮对应节点。
- 节点断点状态要能在保存和重新加载模板后保持一致。

### 4.2 `callWorkflow` 配置

- 步骤库中新增 `callWorkflow` 分类或条目。
- 配置面板最少包含：目标模板、参数映射、输出变量。
- 若暂时不提供模板下拉，也要提供明确的模板 ID 输入与校验提示。

### 4.3 数据步骤配置

- `convertJson`：配置输入变量、转换方向、输出变量。
- `extractKey`：配置输入变量、keyPath、输出变量。
- `randomGet`：配置输入变量、输出变量。
- 这些步骤必须纳入导入导出、模板保存加载与校验闭环。

## 5. 测试重点

1. mock E2E：节点断点设置、取消与命中高亮。
2. mock E2E：变量检查器展示、暂停态按钮切换。
3. mock E2E：`callWorkflow` 与数据步骤配置表单、保存和重载。
4. 真实联调：断点命中暂停、继续、单步、变量快照与预览共存。
5. 真实联调：`callWorkflow` 执行路径、子流程失败定位与结果写回。
6. 0.0.6 的预览、全屏、左右端口和编辑器体验回归。

## 6. 实施顺序

1. 扩 `runStore` 的调试状态模型与控制动作
2. 扩 `RunPanel` 断点与变量检查器 UI
3. 补编辑器节点断点状态与命中定位
4. 扩 `stepRegistry`、`NodeConfigPanel`、`validator`、`canvasConverter`
5. 补 mock 与真实联调回归

总结：0.0.7 前端的重点是把调试台从“只看预览”升级成“可停、可查、可恢复”，同时让复用和数据步骤的配置链路真正可用。
