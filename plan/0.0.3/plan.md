# 0.0.3 版本目标（运行可靠性 + 模板交换）

导语：本版本聚焦把 0.0.2 的工程底座转化为更“可用”的产品能力，优先补齐模板导入/导出与运行可观测性短板。

## 1. 版本目标

| 目标项 | 优先级 | 说明 | 验收信号 |
|---|---:|---|---|
| 模板导入/导出（JSON） | P0 | 首页导入模板文件；模板卡片支持导出当前模板 | 导入后可编辑/可运行；导出文件可被再次导入 |
| 步骤失败事件（STEP_FAILED） | P0 | 执行器失败时能定位到失败步骤与错误码 | WS 事件链出现 `STEP_FAILED` 且携带 `stepId + error` |
| WS 心跳协议与收包处理 | P0 | 后端不再因客户端心跳消息积压导致断线 | 连接长时间保持稳定；服务端可忽略/回包心跳 |
| 黑盒回归扩展（取消/失败路径） | P1 | 用自动化把关键异常路径固定下来 | 脚本/E2E 覆盖 cancel 与失败事件 |

## 2. 版本边界（不做）

- 不引入 if/loop 等控制流节点（留到后续版本）。
- 不引入登录、多租户、调度系统。
- 不进行大规模 UI 视觉重设计，仅补齐现有交互缺口。

## 3. 交付物清单

- `plan/0.0.3/requirements.md`
- `plan/0.0.3/steps/{api.md,backend-plan.md,frontend-plan.md}`
- `report/0.0.3/{tech.md,test.md,result.md}`
- `test/0.0.3/*`（自动化脚本/用例）

总结：0.0.3 以“模板交换 + 运行稳定可观测”为主线，确保演示与扩展都有更扎实的产品基线。
