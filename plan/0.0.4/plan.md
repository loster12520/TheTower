# 0.0.4 版本目标（步骤扩展 + subflow 控制流）

导语：本版本聚焦把 TheTower 从“线性 MVP”升级到“可表达控制流的工作流编辑器”，优先补齐步骤体系，并用 subflow 方案承载 IF/For/While 等容器步骤。

## 1. 版本目标

| 目标项 | 优先级 | 说明 | 验收信号 |
|---|---:|---|---|
| 步骤体系扩展 | P0 | 对标 AdsPower 补齐页面操作、等待、获取数据、数据处理、流程管理步骤 | 新增 stepType 可在前后端保存、校验、运行 |
| 控制流 subflow 表达 | P0 | 用容器节点内嵌 subflow 小画布承载 `if/for/while/startBrowser` 的子步骤 | 用户可直接在容器节点内拖拽、连线、保存子流程 |
| 递归执行与路径高亮 | P0 | 后端从线性执行升级为递归执行，并通过 `stepPath` 回传嵌套执行位置 | 前端可同时高亮主节点与 subflow 内步骤 |
| 参数对齐与配置增强 | P0 | 将关键步骤参数与 AdsPower 参数表对齐 | 新步骤配置可覆盖 P0 参数集 |
| 模板兼容与结构升级 | P1 | 在不破坏旧模板的前提下升级到 0.0.4 schema | 旧模板仍可读取、保存、运行 |

## 2. 版本边界（不做）

- 不做第三方工具步骤（2Captcha、OpenAI）。
- 不把主画布升级成任意 DAG 编辑器；每一层流程仍要求线性。
- 不支持跨层连线：主流程与 subflow 之间、不同 subflow 之间不直接连线。
- 不在本版引入调度系统、账号环境资产管理、多租户。
- 不在本版引入高级编辑能力，如跨层复制粘贴、批量编辑、分支并排展开总览。

## 3. 核心方案摘要

### 3.1 画布表达
- 主流程仍是一张根画布。
- `if/for/while/startBrowser` 渲染为大型容器节点。
- 容器节点内部包含一个可预览、可激活编辑的 subflow 小画布。
- `if` 支持 `THEN/ELSE` 双分支切换，其余容器节点使用 `BODY` 单分支。

### 3.2 数据结构
- 根流程仍保存为 `steps: Step[]`。
- 容器步骤在保存时把 subflow 编译为 `config.then/config.else/config.body: Step[]`。
- 前端编辑态允许维护 subflow 的 `nodes/edges`，但不直接持久化 ReactFlow 运行时字段。

### 3.3 执行与可观测性
- 后端执行器从顶层顺序遍历升级为递归执行步骤树。
- WS 事件统一增加 `stepPath`，例如 `["if-1", "then", "click-1"]`。
- 前端运行态按 `stepPath` 同步高亮容器节点与 subflow 内部步骤。

## 4. 分阶段推进

### Phase A：协议与文档收口（P0）
- 完成 `plan/0.0.4/requirements.md`
- 完成 `plan/0.0.4/steps/{api.md,frontend-plan.md,backend-plan.md}`
- 明确容器步骤字段、事件结构、错误码与兼容策略

### Phase B：后端控制流基线（P0）
- 扩展步骤校验器
- 实现 `if/forTimes/while/break` 的递归执行骨架
- 为步骤事件增加 `stepPath`
- 保持旧线性模板兼容运行

### Phase C：前端 subflow 编辑能力（P0）
- 新增容器节点渲染
- 新增 subflow 预览态与激活编辑态
- 改造 editor store，支持 subflow 状态与递归转换
- 改造运行态高亮逻辑

### Phase D：步骤补齐与联调（P1）
- 页面操作与键盘操作补齐首批 P0 节点
- 获取数据与数据处理补齐首批 P0 节点
- 联调保存、加载、运行、失败路径
- 补自动化测试与黑盒回归

## 5. 主要风险

| 风险 | 影响 | 缓解策略 |
|---|---|---|
| 多层 ReactFlow 嵌套导致拖拽/缩放冲突 | 前端编辑体验不稳定 | 同时只激活一个 subflow，非激活态仅做预览 |
| 保存/加载转换错误导致子流程丢失 | 模板数据损坏 | 将 subflow 编译/逆编译逻辑独立为工具函数并补测试 |
| 递归执行改造破坏旧线性步骤 | 运行链路回归 | 保留旧模板回归用例，按 stepType 分批启用控制流 |
| 新事件字段影响前端旧解析逻辑 | 联调失败 | 事件字段采用“新增不替换”策略 |

## 7. 版本完成判定

1. 用户可在容器节点内通过 subflow 方式编排子步骤。
2. 模板保存、重新加载后，subflow 结构不丢失。
3. 后端可运行至少一条包含控制流的模板，并通过 `stepPath` 返回嵌套执行路径。
4. 旧版线性模板不报错，仍可运行。
5. 0.0.4 的计划、需求、步骤设计、测试与总结文档结构完整。

总结：0.0.4 的核心不是单纯“再加几个节点”，而是把 TheTower 的流程表达能力从线性串行提升到“线性主流程 + subflow 控制流”的下一阶段。
