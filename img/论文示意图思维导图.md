## 图4-1 系统架构示意图

**原图**：[fig_4_1.png](./fig_4_1.png) ｜ **思维导图渲染**：[fig_4_1_mindmap.png](./fig_4_1_mindmap.png)

### 结构化思维导图

```
TheTower 系统架构
├── 前端展示层 (React + Umi + ReactFlow)
│   ├── 画布编排模块 → 节点拖拽·连线·自动布局
│   ├── 配置面板模块 → 节点参数·运行参数
│   ├── 运行监控模块 → 状态·日志·产物
│   ├── 调试工作台模块 → 断点·单步·远程操控
│   └── 协作界面模块 → 在线成员·差异采纳
├── 通信协议层
│   ├── REST 接口 → 模板·运行·调试·认证
│   └── WebSocket 推送 → 运行事件·调试事件·协作事件
├── 后端服务层 (Ktor + Kotlin)
│   ├── 模板服务 / 运行服务 / 调试服务
│   └── 认证服务 / 调度服务 / 协作服务
├── 执行引擎层 (Playwright)
│   ├── 流程执行器 → 步骤解析·上下文管理
│   └── 浏览器驱动 → Chromium·Firefox·WebKit
└── 数据存储层
    ├── SQLite 数据库 → 模板·运行·用户·调度
    └── 文件存储 → 运行产物·协作数据
```

### 关键要素

- **五层架构**：前端展示层 → 通信协议层 → 后端服务层 → 执行引擎层 → 数据存储层
- **双轨通信**：REST 处理请求响应明确的操作，WebSocket 推送实时事件
- **解耦设计**：前端专注图形建模与交互，后端聚焦流程编译、状态管理与自动化执行

## 图4-3 核心数据模型ER图

**原图**：[fig_4_3.png](./fig_4_3.png) ｜ **思维导图渲染**：[fig_4_3_mindmap.png](./fig_4_3_mindmap.png)

### 结构化思维导图

```
核心数据模型
├── WorkflowTemplate（模板）
│   ├── id(PK) / name / description / schemaVersion
│   ├── steps(有序数组) / otherStep(零散节点与边)
│   ├── createdAt / updatedAt / stats / lastRun
│   ├── 1──N→ Run
│   └── 1──N→ Step
├── Run（运行）
│   ├── id(PK) / templateId(FK)
│   ├── status: PENDING | RUNNING | SUCCEEDED | FAILED | CANCELED
│   ├── currentStepId / startedAt / finishedAt / error
│   └── 1──N→ RunEvent
├── RunEvent（运行事件）→ type / stepId / data / timestamp
├── Step（步骤）→ type(节点类型) / config(参数配置)
├── Workspace（工作空间）→ id(PK) / name / ownerId → 1──N→ WorkflowTemplate
└── User（用户）→ id(PK) / username / password → 1──N→ Workspace
```

### 关键要素

- **核心实体**：WorkflowTemplate（模板）与 Run（运行）是系统两大核心实体
- **定义与实例分离**：模板是流程定义的持久化载体，运行是模板执行的实例
- **状态枚举**：Run.status 包含 PENDING → RUNNING → SUCCEEDED/FAILED/CANCELED
- **层级关系**：User → Workspace → WorkflowTemplate → Run → RunEvent

## 图5-1 前端编排交互流程时序图

**原图**：[fig_5_1.png](./fig_5_1.png) ｜ **思维导图渲染**：[fig_5_1_mindmap.png](./fig_5_1_mindmap.png)

### 结构化思维导图

```
前端编排交互流程
├── 阶段1：画布编排
│   ├── 用户→画布：拖拽节点、连线、配置参数
│   ├── 画布→REST API：PUT /templates/{id} 保存步骤
│   └── REST API→画布：保存成功响应
├── 阶段2：发起运行
│   ├── 用户→画布：点击运行
│   ├── 画布→REST API：POST /runs
│   └── REST API→RunService：创建 Run 记录
├── 阶段3：浏览器初始化
│   ├── RunService→PlaywrightRunExecutor：创建浏览器上下文
│   ├── PlaywrightRunExecutor→Playwright：启动浏览器
│   └── Playwright→PlaywrightRunExecutor：浏览器就绪
├── 阶段4：步骤执行循环
│   ├── RunService→WebSocket：RUN_STARTED
│   └── loop 逐步执行 steps
│       ├── Session→WebSocket：STEP_STARTED
│       ├── Session→Playwright：执行浏览器操作
│       └── alt: 成功→STEP_SUCCEEDED / 失败→STEP_FAILED
└── 阶段5：运行完成与状态回传
    ├── Session→WebSocket：RUN_SUCCEEDED / RUN_FAILED
    ├── WebSocket→运行监控：事件推送
    └── 运行监控→用户：实时状态展示
```

### 关键要素

- **五阶段流程**：画布编排 → 发起运行 → 浏览器初始化 → 步骤执行循环 → 运行完成
- **事件驱动**：每个步骤开始/成功/失败均产生事件，通过 WebSocket 推送
- **无需轮询**：前端通过 WebSocket 持续接收事件流，实时渲染执行进度

## 图5-2 后端执行引擎时序图（拆分为 a/b）

**原图**：[fig_5_2.png](./fig_5_2.png)

### 图5-2a 初始化与执行主循环

**思维导图渲染**：[fig_5_2a_mindmap.png](./fig_5_2a_mindmap.png)

```
后端执行引擎 — 初始化与执行主循环
├── 入口：RunService 接收运行请求
│   ├── 创建 Run 记录 (status: PENDING)
│   ├── 返回 runId
│   └── 启动独立协程
├── 浏览器初始化：PlaywrightRunExecutor
│   ├── 解析浏览器类型与启动参数
│   ├── 创建浏览器实例 (Chromium/Firefox/WebKit)
│   ├── 创建页面上下文
│   └── 更新 Run.status → RUNNING
└── 执行主循环：PlaywrightRunSession
    ├── 遍历 steps 数组
    ├── 每步：STEP_STARTED → 查找执行分支 → Playwright API → 操作结果
    ├── alt 成功 → STEP_SUCCEEDED + 继续下一步
    ├── alt 失败 → STEP_FAILED + 终止循环
    └── 每步之间检查协程取消状态
```

### 图5-2b 特殊节点与取消机制

**思维导图渲染**：[fig_5_2b_mindmap.png](./fig_5_2b_mindmap.png)

```
后端执行引擎 — 特殊节点与取消机制
├── 特殊节点处理
│   ├── saveData/saveExcel/importExcel → 写入运行产物目录
│   ├── listenRequestTrigger → 注册路由拦截器
│   └── listenRequestResult → 获取累积请求/响应数据
├── 取消机制
│   ├── 用户点击取消 → 协程取消信号
│   ├── 下一步开始前检测取消
│   ├── 释放浏览器资源
│   └── 发送 RUN_CANCELED 事件
└── 运行结束
    ├── 全部成功 → RUN_SUCCEEDED + status: SUCCEEDED
    └── 任一失败 → RUN_FAILED + status: FAILED
```

### 关键要素

- **三层执行架构**：RunService（调度）→ PlaywrightRunExecutor（浏览器管理）→ PlaywrightRunSession（步骤执行）
- **独立协程**：每个运行在独立协程中执行，支持取消控制
- **错误隔离**：Playwright 异常被 try-catch 捕获并转换为标准错误码
- **取消安全**：每步之间检查取消信号，保证资源及时回收

## 图5-3 调试会话状态机

**原图**：[fig_5_3.png](./fig_5_3.png) ｜ **思维导图渲染**：[fig_5_3_mindmap.png](./fig_5_3_mindmap.png)

### 结构化思维导图

```
调试会话状态机
├── IDLE（空闲）
│   └── → 启动调试运行 → DEBUGGING
├── DEBUGGING（调试执行中）
│   ├── → 命中断点 → PAUSED
│   ├── → 步骤成功 → DEBUGGING（继续）
│   ├── → 步骤失败 → FAILED
│   ├── → 用户取消 → CANCELED
│   └── → 全部完成 → SUCCEEDED
├── PAUSED（断点暂停）
│   ├── → 继续执行/单步执行 → DEBUGGING
│   ├── → 远程操控/查看上下文/时间旅行 → PAUSED（自环）
│   └── → 用户取消 → CANCELED
├── SUCCEEDED（调试成功完成）→ 终态
├── FAILED（调试执行失败）→ 终态
└── CANCELED（用户取消）→ 终态
```

### 关键要素

- **六种状态**：IDLE → DEBUGGING ↔ PAUSED → SUCCEEDED/FAILED/CANCELED
- **断点暂停**：条件断点或命中次数条件满足时暂停，发送 DEBUG_BREAKPOINT_HIT
- **调试交互**：暂停状态下支持继续执行、单步执行、远程操控、上下文查看、时间旅行

## 图5-4 WebSocket实时通信时序图（拆分为 a/b）

**原图**：[fig_5_4.png](./fig_5_4.png)

### 图5-4a 运行与调试事件流

**思维导图渲染**：[fig_5_4a_mindmap.png](./fig_5_4a_mindmap.png)

```
WebSocket — 运行与调试事件流
├── 连接：/ws/v1/runs/{runId}
├── 运行事件流
│   ├── RUN_STARTED → 初始化进度视图
│   ├── STEP_STARTED → 高亮当前步骤
│   ├── STEP_SUCCEEDED → 填充步骤结果
│   ├── STEP_FAILED → 展示错误信息
│   ├── RUN_SUCCEEDED / RUN_FAILED / RUN_CANCELED → 更新运行状态
│   └── LOG → 日志输出
└── 调试事件流
    ├── DEBUG_SESSION_STARTED → 调试会话建立
    ├── DEBUG_BREAKPOINT_HIT → 暂停执行
    ├── DEBUG_CONTEXT_UPDATED → 刷新变量
    ├── DEBUG_FRAME → 更新预览画面
    └── DEBUG_STEPPED → 单步完成
```

### 图5-4b 协作事件流

**思维导图渲染**：[fig_5_4b_mindmap.png](./fig_5_4b_mindmap.png)

```
WebSocket — 协作事件流
├── 连接：/ws/v1/templates/{templateId}/collaboration
├── 协作事件流
│   ├── COLLAB_PRESENCE → 更新在线成员
│   ├── COLLAB_REMOTE_PATCH → 提示远端保存
│   └── COLLAB_CONFLICT → 展示差异摘要
├── 冲突处理
│   ├── 版本时间一致 → 自动采纳差异
│   └── 版本冲突 → 用户选择：采纳远端/保留本地
└── 统一消息格式：eventType + timestamp + payload
```

### 关键要素

- **双通道设计**：运行事件通道 + 协作事件通道，各自独立
- **三类事件**：运行事件（8种）、调试事件（5种）、协作事件（3种）
- **统一消息格式**：eventType + timestamp + payload 三段式结构
- **前端分发模式**：根据 eventType 将事件分发至对应的状态更新逻辑
